Fix EDITOR-API-002: session mirror persists applied op, reload restores it dirty
Date: 2026-10-13

## Finding (from in-prog-logs/current-main-resweep-editor-revision.tsv, shared main)

EDITOR-API-002 PRESENT/REPRODUCED: editor.js postAll (:238-249) called
setDraftRevision(handle, rev) -- which persists the whole draft to
sessionStorage -- BEFORE dropping the just-applied op from the in-memory
draft; the drop was never re-persisted (persist is not exported from
drafts.js). After a partial save (op1 200, op2 422/409) the mirror kept the
applied op; a reload (fresh drafts.js memory over the same sessionStorage)
restored it as still-pending/dirty.

## Reproduction

.scratch/fix-editor-draft-mirror-20261013/probe_api002.mjs drives the REAL
editor.js/drafts.js/api.js headless under node v22 (stubbed
document/window/sessionStorage/fetch, click the real Save button). Pre-fix
run: mirror = {"revision":"rev-1","fields":{"status":"approved"},...}
while memory fields={} ; reload restores fields:{status:"approved"},
dirty=true. VERDICT: BUG (exit 1). Post-fix: mirror fields={}, reload
clean of the applied op, pending body survives. VERDICT: OK (exit 0).

## Fix

- drafts.js: setDraftRevision replaced by dropAppliedOp(handle, op,
  revision) -- drops the applied op (set_field / set_body+pins /
  add_link/remove_link, same branches postAll had), records the revision,
  and persists once at the end. Memory and the mirror can no longer
  disagree about which ops are pending.
- editor.js: postAll now calls dropAppliedOp(handle, one, rev) instead of
  setDraftRevision + the inline mutation; import updated. setDraftRevision
  had no other callers (grep over src/ docs/ tests/ is clean).

## Test

tests/test_editor_draft_mirror.py: node-driven pytest (same posture as
test_vscode_extension.py's node execution, skipif no node; one spawn,
120 s timeout). Scenario "partial": field op applies (200 rev-1), body op

clears the draft, mirror key gone, reload not dirty. Verified red against
