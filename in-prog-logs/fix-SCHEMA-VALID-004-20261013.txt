## Fix

One seam: src/refdes/schema.py, in the field loop that constructs the only
`FieldSpec` in the codebase (single construction site — grep `FieldSpec(`).
When `type` is in `NON_SCALAR_FIELD_TYPES` (imported from model.py, the one
shared constant the loader and the editor already consult) and `default` is
present but not a list -> `SchemaError` with the
`types.<type>.fields.<field>.default` path convention.

Why schema-load and not parse.py's default-copy (1106-1107/1116): the
mistake is the schema's, not any item's; parse.py has no schema file/line to
report it against, and reporting it per item would blame items whose own
text is correct. The load seam fails once, points at the file the author
edits, and — because FieldSpec has one construction site — also covers
presets/sets/migration-merged schemas. The parse-side copy needs no change:
after load-time validation a non-None `FieldSpec.default` on a collection
field is always a list.

Message keeps `parse._reject_scalar_collection`'s posture: refuse-don't-
split, and the comma/substring consequence is named only when the default
string actually contains a comma (bare `default: "power"` gets no substring
claim — a search for "power" does find it).
