--- The change ---

`src/refdes/citations.py`: new `_outline_hints(want, titles, limit=5)`, and the
KIND_NO_MATCH branch calls it instead of `difflib.get_close_matches(...)`.
Ranking, in tiers, so the hint is explainable rather than a score the author
cannot reproduce:

    0  same title, differing only in case (casefold equal)
    1  one is a prefix of the other      -- truncated title, or the outline's
                                           `8 ` numbering the citation dropped
    2  one contains the other            -- 'Regulatory Information' vs 'Regulatory'
    3  difflib ratio >= 0.6              -- a plain typo, unchanged from today

Within a tier: ratio descending, then outline order (so ties are stable and the
same outline always prints the same hint). Capped at 5, as before. Tier 1/2
guard against an empty title so a blank outline entry can't prefix-match
everything at ratio 0.

`.scratch/p2_after.txt` — after: `Therma` -> 'Thermal Information',
`Electrical` -> 'Electrical Characteristics', `Ordering` -> 'Ordering
Information', `Regulatory Information` -> 'Regulatory' first. Everything the
report already got right still comes out the same.

Deliberately unchanged:
* Resolution. `match_outline_title` still compares `_norm(title) == want`
  case-sensitively and refuses ambiguity; the hint is computed strictly after
  both of those, and nothing in it is ever resolved for the author. The new
  test asserts this structurally: every one of its 15 cases is inside
  `pytest.raises`, so a fuzzy match that started *resolving* would fail the test
  rather than pass it.
* The hint still prints the normalised title (as `get_close_matches` did), not
  the raw stored one — a title stored with an embedded tab/newline
  (ds-ws.pdf's case) stays printable in a one-line diagnostic.
* Nothing else. I checked whether this helper is shared with the other
  diagnostics: it is not. Every other "did you mean" in the tree is its own
  inline `difflib.get_close_matches` at its own cutoff — `parse.py:314`
  (field names), `parse.py:822-823` (link/field names), `schema.py:119/197/386/403`
  and `configcheck.py:165` (setting/type names), `sources.py:280` (source keys),
  `cli.py:282/291/324/1172` (board/type names), `blocks.py:85`, `theme.py:358`,
  `scaffold.py:357/550`, `standards.py:430/613`, `build.py:232`. Introducing a
  shared helper would have changed all of them at once with no evidence any of
  them wants it; the change is scoped to the section hint, which is what the
  report's finding is about. citations.py:418 was the only difflib call in
  citations.py, so the import stays used.
