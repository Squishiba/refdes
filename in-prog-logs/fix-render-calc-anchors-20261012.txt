## Anchor strategy chosen (and why)

Emission is NOT changed. The owner's own item page keeps the bare
`id="calc-<name>"`, which is exactly what `[[ID#calc:name]]` resolves to
(href = `<owner-slug>.html#calc-<name>`, always page-prefixed, so it lands
on the standalone page from anywhere — including from document.html, where
_anchorize's PAGE_HREF_RE deliberately does not touch fragment hrefs). That
keeps every generated cross-reference and every published deep link working
byte-for-byte, which the review note asked to preserve.

Uniqueness is then enforced where it is actually a property: one rendered
page. `render._write_html` is documented in this repo as "the single seam
every HTML page in the site is written through" (verified: it is the only
template.render/write site in render.py, and serve's preview rebuilds via
render_site -> the same seam). A `_unique_calc_anchors` pass runs there: the
first `calc-*` id in document order keeps its anchor; each later repeat on
that page moves to `-2`/`-3`…, with the candidate checked against every id
already on the page (so a genuine block named `losses-2` can never be
squashed). Non-calc ids are never renamed (field-/cite- anchors only exist
on item pages, where per-item validation already forbids repeats).

This covers document.html, the board/workspace document copies, log pages,
calcblock pages, and item pages (no-op) with one mechanism and no state
threaded through the templates.
