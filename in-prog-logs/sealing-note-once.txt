Reproduced on this branch first (verified, not assumed): scratch project in

Mechanism chosen (task: "same mechanism or the same state" as the
`.refdes/schema.json ... refreshed` note): refreshed achieves once via state
in a gitignored file under `.refdes/` (schema.json's mtime) that a writable
run refreshes, with `write=False` (--no-write/--dry-run) skipping the write
while keeping the verdict (schema_json.write_schema, src/refdes/schema_json.py:404).
The set (not mtimes) is the right state here, because the config can be
edited back to a set the note already announced. So:
- `.refdes/sealing-optin.json` records `{"opted_in": [sorted set]}`.
- `_announce_sealing_optin(project, write=, verbose=)` prints when the set
  differs from the record (or under --verbose), and a writable run records
  the current set. Removal of the overlay is recorded (silently, as []), so
  re-adding prints again. Corrupt/missing record reads as "never announced"
  (self-heals, mirrors keys.is_adopted's read-None pattern).
- `--no-write`/`--dry-run` print by the same rule, record nothing.
- `--verbose` (decided, stated in PR): always prints; records as usual, so
  a verbose run on an unannounced set IS that set's announcement.
- Refused marker write mirrors write_schema: append to load_writes.blocked +
  project.warn(read_only_refusal, file=...).
- Small refactor: `_writes_allowed(args)` factored out of `_load`'s
  `not (args.no_write or args.dry_run)` expression, shared by the load and
  both announce call sites.

Verified by hand in .scratch/f10-proj: first check prints, second is silent;
--no-write on a fresh tree prints and leaves no marker; writable run after
still prints, then quiet; -v always prints; removal → re-add prints once.
