FINDING 1: TXN-ROLLBACK-001 (PR #163, HIGH) — RE-CONFIRMED on d71c143
=====================================================================

Claim: the `except Refused` handler around `_refresh_display_halves` in
`revise.apply` calls `_rollback()` while `refresh_rewrites` is still empty,
so refresh writes that landed stay on disk while the run prints "rolled
back.". Line drift: on this checkout the handler is revise.py:1642-1646,
`refresh_rewrites` initialises empty at :1462, `_rollback` is at :1533
(starts `restore_rewrites(refresh_rewrites)`), population loop at :1647-1657
— runs only AFTER the refresh returns. Same shape as the packet describes.

Re-confirmation (real commands, scratch project .scratch/repro-txn001):
  hardware project (custom types), items/req.yaml (REQ-001), dec_a.md and
  dec_b.md each `satisfies: [REQ-001]`, mapping prefixes REQ->BUD.
  1. `refdes check` (writable load) -> "(minted 3 key(s) and rewrote 2
     reference(s) while loading)", both dec files now `REQ-001@ajtez6xsfyg`.
  2. `chmod 0444 items/dec_b.md` (dec_a sorts first -> its refresh write
     lands before the refusal), then `refdes revise mapping.yaml`:

     refused:
       cannot write items/dec_b.md (read-only tree?) -- no item file was
       rewritten and no hash was carried forward, so the tree is exactly as
       it was found. Make the tree writable and run it again.
       rolled back.
     revise exit=1

  3. diff vs pre-run copies: req.yaml unchanged, dec_b.md unchanged, but
     dec_a.md CHANGED: `satisfies: [REQ-001@ajtez6xsfyg]` ->
     `satisfies: [BUD-001@ajtez6xsfyg]`. PRESENT: a landed refresh write
     naming the retired id, stamped "rolled back."

Root cause: ordering. The refresh writes files in path order (plan_expansion
sorts files_touched) and raises on the first refusal; the only account of
what it wrote is the snapshot comparison, which ran strictly after the try
block, so the except path rolled back an empty `refresh_rewrites`.

Fix (src/refdes/revise.py): extracted the population loop into
`_collect_refresh_rewrites()` inside apply() and call it in the except
branch BEFORE `_rollback()` (and once after the refresh as before). Nothing
else changed; write order, messages, exit codes untouched.
