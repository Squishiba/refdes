  adopted", so the plan proceeds and the rewrite clobbers the author's
  file. The changelog.d/store-read-decode-errors.fixed.md fragment claims
  a corrupt marker "refuses with the file named".

- seal._load_seal_data: isfile-guarded -> directory silently = no seals. FIX.

  But adopt.py's own read + write over a directory marker crashes raw at
  write time -> keys adopt must refuse a directory marker too, naming it.

No shared cross-module store-read helper exists (_read_store_file is
history-private and raises HistoryError); each module wraps in its own
error type, matching the #209/#212 pattern.

Fixes applied:
- B9 (directory-store-reader class):

    "... baseline file is a directory, not a file"; load_baseline guard
    isfile->exists so a directory under the exact name routes through it.
  * seal._load_seal_data, ids.load_ledger, boards.load_manifest,
    citations.load_lockfile: isfile->exists guard + IsADirectoryError wrap

    "is a directory, not a file" -- str() names .refdes/citations.yaml).
  * history._read_store_file: one wrap, every reader (load_events scan,
    load_object, save_object/append_event existing-file reads).
  * keys.is_adopted: KEEP the swallow (documented "unreadable = not
    adopted" posture, #212 fragment).

    isfile-guarded; the write transaction would die raw on the directory).
- F12: adopt.apply() parses the UTF-8-clean marker in the plan phase; a

  .refdes/keys-adopted.yaml, "repair it by hand or delete it"; returns
