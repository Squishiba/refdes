# fix-blocked-by-diamond-cycle

TASK: a blocked_by diamond (two paths that reconverge) must not be reported
as a cycle.

## Verification of task claims (all confirmed on this branch, main 6d6d633)

- src/refdes/blocks.py `_walk` (~line 389): `if target_id in visited: if
  on_cycle == "error": raise CascadeCycleError(path + [target_id])` —
  `visited` is ONE global set (seeded in `walk_cascade`, line 342), so ANY
  revisit raises under on_cycle="error", reconvergence included. Confirmed.
- src/refdes/blocked.py:89-90 calls `walk_cascade(..., on_cycle="error")`
  for every item declaring `blocked_by`. Confirmed.
- blocked.py discards the walk's returned node tree — the walk is a pure
  cycle check; root resolution is the separate `_paths_to_roots` recursion.
  This drove the design decision below.

## Repro (fresh project, hardware@3)

`refdes init` in .scratch/diamond-repro (standard: hardware@3), then four log
items in items/io/ (markdown front-matter, links as top-level keys):
LOG-IO-004 (leaf), LOG-IO-003 blocked_by [LOG-IO-004], LOG-IO-005
blocked_by [LOG-IO-003, LOG-IO-004] — the exact PR #291 shape. `refdes check`:

    ERROR   items/io/log-005.md:2 [LOG-IO-005] — blocked_by cycle: LOG-IO-005 -> LOG-IO-004
    (minted 2 key(s) and rewrote 3 reference(s) while loading)
    4 items, 1 errors, 0 warnings
    exit=1

Confirmed: LOG-IO-004 is reached by two paths (005->004 and
005->003->004) — no cycle, but reported as one.

## Fix

blocks.py `_walk`: under on_cycle="error", raise CascadeCycleError only when
the target is on the CURRENT path (`target_id in path`) — a true cycle.
A visited target not on the path (reconvergence) is marked
`already_shown=True` as in mark mode and not re-walked.

Decision on reconvergence (per task step 2): shown once as `already_shown`,
NOT re-walked. blocked.py discards the tree entirely (it only needs the
raise/don't-raise signal), so nothing there needs re-walking; and mark mode
— what {{cascade}} renders — keeps its exact visited-set semantics (the
tree.py header comment describes exactly this "expand once, reference
everywhere" rule). Re-walking shared subtrees in "error" mode would also
risk exponential blowup for no consumer's benefit.

Docstrings updated to match: CascadeCycleError ("revisit" -> closing an edge
back to a node on the CURRENT path; diamonds marked, never raised) and
walk_cascade's on_cycle paragraph. on_cycle="mark" behavior unchanged.
