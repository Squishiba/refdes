## The rule chosen

Single consistent rule, two layers, both keyed on the same containment idea
already used by `citations.classify` (src/refdes/citations.py:178-199) and
`serve/upload._validate_dest`: project-relative, slash-separated, no
traversal, and *inside the root by real path*.

1. **Config half** — `schema._confined_asset_dirs`, called from
   `load_project` on `site.assets:`. A SchemaError at load (voice:
   `refdes-project.yaml: site.assets entry '../' escapes the project
   root; declare a directory under it`) for: backslashes, absolute
   entries, lexical traversal (`..` after normpath), the root itself in
   any spelling (`.`, `""`, `a/..`, or a symlink resolving to the root —
   it would walk `_site/` and `.refdes/` back into the published assets),
   and real paths leaving the root (symlink escapes at load). Entries are
   canonicalized (`./pics/../shots/` -> `shots`), so the readers see one
   spelling. A *missing* directory still passes the load — its absence
   stays the build's existing `not a directory` warning.
2. **Runtime half** — `build.walk_site_assets`, one generator all three
   asset walks now share (review round 1: the load check alone cannot see
   the tree move after load; review round 2: filtering after enumerating
   is already reading the outside tree):
   - a *declared directory* whose realpath is not strictly under the root
     is not entered by `os.walk` at all (post-load retarget, including
     intermediate segments);
   - each *file* is realpath-checked at walk time and yielded as
     contained/not;
   - `serve.state.asset_files` (poller watch set, and the picker's
     `api._images` list through it) takes only contained files, silently;
   - `collect_static_assets` warns naming an escaped directory once or an
     escaped file per file, and registers neither;
   - `_search_image_matches` (also used by the HASH_FORMAT 5 image hash
     pass) cannot bare-resolve through an escaping symlink, so the build
     reports the honest unresolved error instead.

Watcher and build cannot drift because they literally call the same
function; `serve.upload._on_search_path` (realpath comparison against the
declared dirs) stays consistent with it: files the search skips are not on
its search path either.

## Difficulties

- The shared venv's editable install points at main's checkout: every CLI/
  runtime claim above was made with this worktree's `src` first on
  `sys.path`/`PYTHONPATH` (`python3 -m refdes.cli`, global `-c` before the
  subcommand — `check --config` is not a thing), and `refdes.__file__`
  printed to confirm which tree answered.
- The first three runtime symlink tests were silently green-ish in the
  wrong direction: a `../` link from `figures/` lands at the project root,
  not outside it — the outside files needed `../../`. Caught by the
  assertions failing, fixed, re-verified.
- Two review rounds shaped the runtime layer (see rule section): load-only
  checking missed post-load symlink moves; post-walk file filtering missed
  the directory-enumeration leak. Both addressed; spy test pins the
  second.

## Known limits (precise)

- TOCTOU: between any realpath check and the syscall that follows (or
  during one poll step), the tree can be swapped again; the shared walk
  shrinks the window from "since the config loaded" to one step, not to
  zero. Documented in `walk_site_assets`' docstring.
- Confinement here covers `site.assets:` (config and the walks over it).
  Not in this finding's scope, still unvalidated config paths: `site.pages`,
  `site.out`, and `imports:` item paths could also be traversal-capable —
  separate findings if confirmed. Likewise a body `![](../../x.png)`
  multi-segment src resolving outside the root via `_local_image_path` is
  the image-src family (IMAGE-ASSET-001/002 neighborhood), not the
  `site.assets:` walk this commit confines.
- Upload overwriting an *existing* file that is itself an escaping symlink
  is upload.py's (`_validate_dest` checks the directory, not an existing
  target file); not touched here.
