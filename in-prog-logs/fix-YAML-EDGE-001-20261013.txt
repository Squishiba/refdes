## 2. The fix

One call, in the loader that was missing it (`src/refdes/parse.py`):
`_construct_mapping_dupes` now runs `_preserve_surrogate_scalars(node)`
before `_collect_duplicates(loader, node)`, exactly like `_construct_mapping`
and `_construct_key_mapping` already do. Comment in the diff records why.
`_DupSafeLoader`'s docstring said "records a repeated mapping key, and
nothing else"; "nothing else" was the bug, so it now says "adds no
bookkeeping", which is the part that actually has to stay true (a
`__line__` key would be reported by `configcheck` as an unknown setting).

Why this is the right layer rather than a `str(tname)` in `schema.py`: the
retag exists so a surrogate-shaped scalar keeps the spelling its author
wrote, across every hand-authored file refdes reads, and it is already
applied by the other two mapping constructors in this file. The two loaders
disagreeing about the same bytes is the defect; `tname[:3]` was only where
it became loud. Scope stayed in the parser as briefed — no schema.py/cli.py
edit: with the retag the type loads under its own name (prefix `123`, label
from its own `label:`) and the run is green, which is the "valid handling"
outcome, not merely a nicer crash.

After the fix, same probe:
