## Review claim

5f267b2's `id=body.get("id") or None` was said to normalize every falsy
JSON value (0, false, [], possibly {}) to auto-allocation, not just the
empty string the preview treats as absent.

## Reproduction (before touching code)

.scratch/probe-editor-api-010/probe2.py, live EditorApp over HTTP, run
against BOTH the branch src and the shared main checkout at 8b6a52e
(read-only; the run only writes its own temp project). Verdict: the
claimed silent auto-allocation does NOT reproduce, on branch or base.

  base 8b6a52e:  omitted -> 200 REQ-001 | '' -> 422 refused | null -> 200 REQ-002
                 0 / false / [] / {} -> 400 "id must be a string when given" (all four)
  branch 5f267b2: identical, except '' -> 200 REQ-002 (the intended fix)

Why: `_create_item` validates `id` (and destination/amends) as "a string
when given" (api.py, the loop returning "id must be a string when
given") BEFORE the `or None` line is reached. The value's domain at the
collapse is exactly {None, str}, and on that domain `or None` is
observationally identical to a `== ""` collapse. No falsy non-string id
ever reaches the id layer as "empty". The only behavior 5f267b2 changed
is "" (422 -> auto), as intended and tested.

## What was changed anyway, and why

The residual risk is real but structural: `or None` is only safe because
of a gate that sits above it in the function body. A future reorder that
moves the shape gate after CreateRequest construction would silently
turn 0/false/[] into auto-allocations. So the collapse is now spelled
exact-string (`explicit_id = body.get("id")` then
`id=None if explicit_id == "" else explicit_id`), with a comment naming
the gate as the reason the two spellings agree today and the reordering
as the reason they must not diverge later. No behavior change on any
input (probe2 post-change output byte-equal to pre-change).

Tests added in tests/test_serve_create.py:
- test_http_create_refuses_a_falsy_non_string_id_and_allocates_nothing
  (parametrized 0/false/[]/{}): 400 "must be a string", tree byte-
  identical after (snapshot_tree, schema.json excised, repo idiom).
- test_http_create_reads_a_null_id_as_omitted: JSON null stays auto
  (pinning the base behavior so the collapse cannot eat it), takes
  REQ-012.
