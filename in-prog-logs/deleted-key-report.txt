Task: detect and report hand-deleted surrogate keys instead of silently

2026-09-15
- Fast-forwarded from main; already current.
- Read docs/design/keys.md §2 (minting) and §6 Layer 4, then traced the load
  path: cli._load() runs keys.mint_missing() BEFORE build(), so a hand-deleted
  `key:` line was filled with a fresh key and Layer 4 then reported the
  misleading "key changed" — with the evidence already written over.
- Confirmed every minting caller funnels through keys.missing_assignments():
  mint_missing (cli._load), adopt.apply, and plan_missing (keys plan). Gating
  there covers `refdes id`, load-time minting, and adoption at once.
- Added DeletedKey plus deleted_key_records()/deleted_key_message()/
  report_deleted_keys() to keys.py. Evidence precedence is baseline ->
  key-keyed seal files -> key-keyed membership manifest; the first source wins
  and is the one named, and a later source with a different key is reported as
  a disagreement instead of silently picked. Legacy display-id-keyed seal and
  manifest entries carry no key evidence and are skipped, like pre-keys
  baseline entries. A key still declared by a live item is never deletion
  evidence.
- seal.py and boards.py are imported lazily inside _key_evidence_sources();
  both import keys at module level, so a top-level import would be circular.
- Seal files are enumerated from project.boards plus the default board rather
  than the filesystem, matching how the rest of the code resolves seal paths.
- missing_assignments() now excludes items with a deleted-key record, so
  nothing mints over the evidence; mint_missing() warns (project.warn) on both
  the writable and --no-write paths, and validate() reports the Layer 4 ERROR
  with the same verbose message: old key, the record it came from, that
  references and history now dangle, and both remedies (restore `key: <old>`
  or give the item a new display id, which then mints normally).
- adopt.apply() refuses before the generic blocking-errors gate, so the user
  gets the specific explanation rather than "project has existing build
  errors".
