```
WARNING <project> — SOURCE FILE CHANGED: 'analysis/budget.csv' no longer matches its pin, but the build is still using the LOCKED values, not the file -- 'rail_load': locked 1.85, but the file can no longer supply it (/home/jorb/.../p4/analysis/budget.csv: no row has the key 'rail_load') [used by DEC-001]. ## Does P4 reach an HTTP client? **YES.** The report's "over HTTP that promise
```
holds" is wrong, and this is the load-bearing finding of the task.

`in-prog-logs/pdf-picker-exercise.md:315` says "Over HTTP that promise holds —
I checked every response I got from a changed-file project for `/home/jorb`
and the item payload and the sources list were both clean."

Those two surfaces *are* clean, and I verified why rather than taking it on
trust:

- The only `serve`-side caller of the reader, `citations.stage_source_pins`
  (`citations.py:1356`), already passes `label=canon`, so the accept path never
  composed an absolute path.
- `grep -rn "resolve_citations" src/` → no hits; `citations.verify` is the entry
  point and `serve` does not call it directly.
- `grep -rn "\.warnings\|\.errors" src/refdes/serve/*.py` → **empty**. The
  diagnostic lists are not serialised into any API response at all.

**But the rendered preview carries it.** `citations._source_drift`
(`citations.py:801-852`) runs on every build and stores its sentence on the
calc line (`citations.py:845`, `line.source_drift`), which `build.py:2120-2122`
renders into the item page:

```python
if line.source_drift:
    ... f'<span class="calc-source-drift">&#9888; {_esc(line.source_drift)}</span>'
```

`refdes serve`'s `PreviewManager.render` (`src/refdes/serve/preview.py:77-92`)
calls `render_site(project, draft=True)` — the same renderer — and serves the
result at `/preview/<item>.html`.

**Measured.** `refdes serve --no-open --port 18731 --token-file …` against
`.scratch/p4-serve`, then an authenticated `GET /preview/dec-001.html` →
**HTTP 200**, body containing:

```html
<span class="calc-source-drift">&#9888; analysis/budget.csv changed: &#39;rail_load&#39; locked 1.85, but the file can no longer supply it (/home/jorb/.paseo/worktrees/16msma8v/citation-absolute-path-leaks/.scratch/p4-serve/analysis/budget.csv: no row has the key &#39;rail_load&#39;) -- accept with: refdes fetch --update --path analysis/budget.csv
```

`grep -c "/home/jorb"` on that response: **1**. The same string is on
`/preview/document.html`. A plain `refdes build` writes it into `_site/`
identically (`.scratch/repro_p4_render.py`: 2 pages carry
`calc-source-drift`), so it also lands in anything published to a static host.

Severity, stated precisely: `/preview/` is behind the launch token, so this is
not an *unauthenticated* leak — a token holder (the author, or anyone handed
the launch URL) reads the server's absolute path and project-root layout. The
`shown()` posture both picker design docs promise is "project-relative paths
only" (`docs/design/editor-source-picker.md:350`,
`docs/design/editor-pdf-picker.md:389`), and it did not hold here. It also
leaks into a published static site, where there is no token at all.

After the fix, the same request returns the same drift message with
`analysis/budget.csv` and `grep -c "/home/jorb"` → **0**.

`grep -n "str(exc)\|strerror\|{exc}\|exc)" src/refdes/citations.py` and the
equivalent over the other two. Each site read and judged:

With a `label` passed, the leak was the error's own text; with none, the path appeared twice. Fixed. |
| `citations.py:1589` `error=str(exc)` on `CitationError` from `classify` | `CitationError` is refdes' own and already spells project-relative paths. No leak; left alone. |

## The changes

`src/refdes/citations.py`
- `fetch_all` now collects `{canonical path: [citing item ids]}` over every
  citation in the project (`cited_by`). The two maps already there cover only
  citations that name a `section:` or a `page:`, and a bare `path:` entry — the
  commonest local citation of all, and the one in the P3 repro — is in neither.
- The local-read `except` in `fetch_all` composes a new
  `_local_read_failure(canon, exc, cited_by[canon], source_keys[canon])` instead
  of `str(exc)`. It reuses `check`'s sentence (`cited local file '…' does not
  exist`, `_resolve_local`, citations.py:1039), falls back to
  `cited local file '…' cannot be read: <strerror>` for any other `OSError`, and
  appends `(cited by …)` for every citing item **and** every `source()` user of
  the file. Placed next to `_section_failure`, which is the same shape of
  message. A remote fetch failure is untouched (`str(exc)` there names a URL).
- All three `_extract_source_values` call sites in this module now pass
  `label=canon` (citations.py:825, 1251, 1705).
- `_extract_source_values`' docstring rewritten: it used to *document* the leaky
  contract ("`fetch` leaves it unset and prints a real path to a terminal"), and
  now says every caller passes it and why the default is not a fallback.

`src/refdes/sources.py`
- `CsvReader.extract`'s `OSError` branch calls the file's own `_cannot_read`
  instead of composing `str(exc)`.

No behaviour changed beyond the message text: same conditions detected, same
remedies named, same exit codes, same severities.
