G1.4 (slug-fallback collision for id-less entries) — CANNOT HAPPEN NOW, SKIP
with recorded why. The label is threads.entry_label = item.id or item.key or
item.slug (threads.py:289). Item.slug is `id.lower() if id else key`
(model.py:665-669) — the slug fallback adds nothing beyond the key, and by
the time cmd_thread builds `v["entries"]`, id-less entries ALWAYS have their
surrogate key: keys.mint_missing runs on the load (keys.py:745; the warm runs
printed "(minted N key(s) ...)" on every scratch project). Keys are 11-char
random alphanumeric minted with `secrets` (keys.py:117-128), duplicate keys
are caught (keys.validate Layer 2, model.add_item keeps both reachable,
model.py:1111-1127), duplicate display ids are a build error (build.py:2898),
and the id/key namespaces are disjoint "display ids contain '-<digits>' and
surrogate keys never contain '-'" (model.py:1099-1105). Repro attempt on
.scratch/g1-slug (root LOG-001 + two id-less siblings): each id-less entry
got its own minted key (8f1z51pe67f / 2s4z5bsbcew), the thread header labels
them distinctly, no collision constructible. The review's premise (slug =
filename stem shared by id-less files) predates the keys work; AGENTS.md
confirms surrogate keys are fully landed.
