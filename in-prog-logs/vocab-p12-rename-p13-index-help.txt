## P12 code (cli.py, revise.py, parse.py)

- `cmd_revise` -> `cmd_rename`; it prints the P12 note to STDERR first when the
  name typed was `revise` (stdout is the command's report, and `--dry-run`'s
  output is what scripts read). Verified: `refdes revise m.yaml --dry-run` with
  stdout redirected to /dev/null shows the note. CORRECTED in fix round 1: the

  names the surrogate key it would mint, and `keys.mint()` draws from
  `secrets.token_bytes`, so that line differs in every run: two `rename
  --dry-run` runs on the same tree differ by it as much as `rename` and
  `revise` do (`.scratch/fix1/probe`, r1/r2/v1/v2 above).
- Module kept as `src/refdes/revise.py`: renaming it is NOT trivial -- it is
  imported by calc_rewrite.py, adopt.py, keys.py, key_restore.py,
  image_freeze.py, links.py, cli.py and by name in tests
  (`from refdes import revise`), so the task's "unless renaming it is trivial
  and touches nothing else" condition fails and the name stays. Docstring
  pointers that named `cmd_revise` were updated to `cmd_rename`.
- Parser: `p_revise` -> `p_rename` for the `rename` subcommand; a second, real
  parser named `revise` carries the alias. WHY A SECOND PARSER AND NOT
  `aliases=`: verified on this Python (3.13.5) that `sub.add_parser("rename",
  aliases=["revise"])` renders the row as `rename (revise)` and the usage line
  as `{...,rename,revise}` -- it shows the alias, which P12 forbids; and that
  `help=argparse.SUPPRESS` on a *subparser* prints the literal `==SUPPRESS==`
  as the row's help text, because a subcommand row is emitted by
  `HelpFormatter._format_action`, which never consults SUPPRESS (only
  `add_argument` gates on it, and it is not on that path for subactions).
  So cli.py gained `_hide_command(sub, name)`: drop the row from
  `sub._choices_actions` and pin `sub.metavar` to the visible commands. It
  runs LAST in the builder (before `parse_args`), because the metavar is
  computed from `sub.choices` at that moment -- called earlier it silently
  drops every later command from the usage line (that is what happened on the
  first attempt; the test would have caught it).
- User-visible strings renamed: the link-verb refusal in revise.py, the
  `unknown type ... see 'refdes rename'` fix line in parse.py, the global
  `--no-write` help, `build --dry-run`'s help, and calc-rewrite's description.
  CORRECTED in fix round 1: `build --dry-run`'s help was NOT renamed in this
  round -- it still read `unlike id/revise/stub-tests` -- and the live refusal
  strings in revise.py still named `revise`. Both fixed under R1/R2 below.
  Prose in lifecycle.py/seal.py/model.py/calc_rewrite.py that names `revise.py`
  the MODULE is left alone (the module is still called that); the two historical
