## What the schema says the shape is

`refdes schema` from `.scratch/b1/`, `$defs.decision__entry.properties.options`:
array of objects, properties `name` / `verdict` / `because`, all strings,
`additionalProperties: false`, no `required`. That matches the panel's own
reads (`opt.get('name')` with an `(unnamed)` fallback, `verdict` defaulting to
`considered`, `because` optional) and the examples in docs/getting-started.md
and docs/authoring.md. So: an option is a mapping; `name` is the meaningful
key but not required; an entry that is not a mapping cannot be rendered at
all. That is the line the validator takes.

## Fix

- `src/refdes/build.py`, `validate_items`: new `elif fspec.type == "options"`
  branch beside the `limit`/`citations` ones. Walks the list and reports one
  error per non-mapping entry through `_field_error`, so it gets the item id,
  the source line, and the `defaults:` attribution the other field errors
  get. A non-list `options:` is left alone on purpose -- that keystroke
  already belongs to `parse._reject_scalar_collection` (`options` is in
  `NON_SCALAR_FIELD_TYPES`), and reporting one keystroke twice helps nobody.
- `src/refdes/templates/item.html.j2`, `document.html.j2`: skip a
  non-mapping entry in the options panel. This is a guard, not the fix.
  `refdes build` renders a project it has already diagnosed (that is the
  run-5 half-written-`_site/` issue, out of scope here), so without it the
  validator error alone still ends in a traceback -- and the traceback
  replaces the diagnostic, which is the part a user can act on. Both
  templates needed it: with only `item.html.j2` guarded, the same item then
  crashed `document.html.j2` on the next page of the same build.

## Not done, on purpose

- `build` still renders past a diagnosed error and writes `_site/` anyway
  (run 5's finding). Unchanged here: the build test asserts the diagnostic
  and the exit code, not that nothing was written.
- The scalar-form message's own advice ("write it as a list ... options:
  [first, second]") is generic loader text and now reads a little oddly for
  `options:`, whose entries are mappings. Left alone -- it is the loader's
  message for every collection field, and changing it is a different diff.
