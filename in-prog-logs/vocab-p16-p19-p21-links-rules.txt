== P19 — verdict: rule holds, proceed ==
Verified "the suffix never tells you whether a link feeds coverage; the
type's satisfying_statuses and verifying_statuses do" against build.py as
above:
- _by never excludes: satisfied_by/verified_by/addressed_by are the very
  names the engine reads as backlinks, and an authored verified_by (legacy
  spelling, build.py:1069-1070 + 859-877) feeds coverage too.
- _by never admits: constrained_by/governed_by/blocked_by never feed it, and
  no status list is consulted for them because the engine never reads the
  pair at all.
- What decides how a coverage pair counts: satisfying_statuses (satisfies),
  verifying_statuses (verifies/verified_by, same gate either spelling).
  addresses is the third pair; its "addressed" stage is by definition the
  record that work was written up and has no status gate (diagram.py:321
  confirms only two gated verbs) — the rule's directive (read the type's
  status declarations, never the name) holds for it too. No verb exists for
  which the SUFFIX decides coverage behavior (constrained_by vs verified_by
  share it and differ), so the no-exception restatement is honest.
