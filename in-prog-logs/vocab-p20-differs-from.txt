Progress 3 (design settled, implementing):

- Shape: `differs_from:` is a non-empty mapping of term name -> one non-empty
  sentence. Wrong shape (scalar/list/empty/whitespace/non-string parts) is a
  SchemaError naming the block path — same posture as `doc:` (configcheck
  BlockChecker.definition for overlays; schema._doc_text for the bundle, which
  bypasses configcheck by design).
- Term-reference validation: runs in schema.load_project after the merge
  (_validate_required_when/_validate_link_targets are the neighbours), so it
  judges the RESOLVED standard on both paths. Namespace of resolvable terms:
  types, link verbs (and their inverse names), sets, and fields declared on
  the same type. Unresolvable = SchemaError with a did-you-mean, matching the
  precedent (error, not warning — see above).
- extends: differs_from joins _NOT_INHERITED (standards.py) — like `doc:`, it
  is the term's own definition text and must not leak from a parent type
  (bound extends requirement would otherwise carry requirement's note).
- Rendering: one fact line per pair, "Differs from <term>: <sentence>", in
  vocabulary.html (dt/dd in vocab-facts; the term links to its page anchor
  when it has one, else plain <code>) and in docs/vocabulary.md
  ("Differs from `term`: …", docs page keeps its own anchors so no link
  there — vocabulary.py cannot know the docs renderer's slugs). A field's
  differs_from renders in that field's Definition cell in the fields table
  of both outputs (fields are not standalone page terms).
- Exports: `refdes schema` JSON gets "differs_from" as an extra annotation
  keyword on the type branch / field fragment / link property where present
  (unknown keywords are inert for JSON Schema consumers); absent =
  byte-identical output, matching the `doc:` precedent's guarantee.
- Golden outputs expected to change: docs/vocabulary.md (regenerate),
  tests/fixtures/hardware3_resolved.json and
  hardware2_design_debate_resolved.json (dataclasses.asdict dumps gain the
  new model field on every object). tests/fixtures/no_theme_build_hashes.json
  is for a no-differs_from note-type project — my rendering is conditional,
  so its vocabulary.html hash must NOT change; if it does, that itself is a
  bug (byte-identity guarantee). Will verify all three against the suite.
