## Pre-work verification (F2)

Run in `.scratch/f2` (`refdes init` + `hardware@3`, a component with a
`citations:` field — confirmed via `refdes schema`, whose `component__entry`
carries the `citations` array; there is no other type with one).

1. **Two citation entries for one path, one per page, are accepted.** Own
   reproduction, not the report's:

   ```yaml
   citations:
     - path: docs/manual.pdf
       page: "2"
     - path: docs/manual.pdf
       page: "4"
   ```

   `fetch` → `fetched docs/manual.pdf sha256=8f5443a56224... hash-only`,
   exit 0. `check` → `1 items, 0 errors, 0 warnings`, exit 0. `build` renders
   **two rows** in the item's citations table, `#page=2` and `#page=4`, and
   `references.html` lists the path once with `CMP-001` twice under "Cited by".
   So the two-entry shape is real and the render is not a duplicate-row bug.

2. **`section:` is *not* the better answer for a span.** Built an 8-page PDF
   with a real outline (two entries, on sheets 2 and 4) and cited
   `section: Thermal Information` on a local path. `fetch` printed
   `section 'Thermal Information' -> page 2` — one entry resolves to exactly
   one page. There is no range form of `section:`; naming a heading gives the
   sheet it starts on, not a span. So the two-entry-per-page shape is the
   answer for a range, and `section:` is the answer for a *heading that moves
   between revisions* (which `docs/markdown.md:446-449` already says), not for
   a span.

3. **The roman-numeral / front-matter case does have a documented answer.**
   `docs/markdown.md:446-449`: "`page:` means the page of the *PDF*, counted from
   1 — the same number the rendered `#page=` fragment opens. A datasheet's own
   printed page number is a different number". A book's front matter is
   numbered in roman numerals, so a roman numeral is the signature of someone
   citing a printed page label; the fix is the PDF's own sheet, counted from 1.

Message design decided: keep the existing rule sentence verbatim, add **one**
remedy sentence, then `See <url>.` — two sentences plus the pointer, so it
still reads short. The remedy sentence is chosen by the *shape* of the refused
value, because the rule alone is not a remedy for the two shapes where someone
believes they really have cited something (a range, a printed page number) and
is a complete answer for the rest (`0`, `-1`, `1.5`, `9 9`). So:

- a range-looking value → one entry per page
- a value with no digits at all (`eight`, `xiv`, `iv`) → count the PDF's own
  pages; one wording covers both a word and a printed page number
- anything else → rule + `See <url>.`, no filler

Status: F2 implemented, verified, committed.

## F2 — done

Message, final form, each shape verified by a literal `refdes check` in
`.scratch/f2`:

```
page: '2-4' is not a page number -- page: must be a positive integer, counted from 1. One entry names one page, so a range is one entry per page for the same path. See https://squishiba.github.io/refdes/troubleshooting.html#citations.
page: 'xiv' is not a page number -- page: must be a positive integer, counted from 1. A printed page number is not a page index: page: counts the PDF's own sheets from 1, the same number the rendered link opens. See https://squishiba.github.io/refdes/troubleshooting.html#citations.
page: '0'  is not a page number -- page: must be a positive integer, counted from 1. See https://squishiba.github.io/refdes/troubleshooting.html#citations.
```

Rule sentence unchanged, one remedy sentence, `See <url>.` — two sentences plus
the pointer. The remedy is chosen by the shape of the refused value (a
`\d+ - \d+` range, including the en/em dashes; a value with no digits at all;
anything else gets nothing because the rule already answers it).
