The change (opencode.json, bash block — eight new deny patterns)
- `*rm -r*`, `*rm -R*`: trailing `*` instead of a space, so a glued flag word
  keeps matching (`rm -Rf x`, `rm -Rv x`) and a bare `rm -rf` / `rm -R` at
  end of line matches. These subsume the old `*rm -r *` / `*rm -R *`, which
  are kept (redundant, harmless, last-wins so order is irrelevant).
- `*rm -?r*`, `*rm -?R*`: `?` = exactly one char, so r/R glued AFTER one
  other short flag: `rm -fr` variants, `rm -vrf`, `rm -frv`, `rm -fR`.
- `*rm -? -r*`, `*rm -? -R*`: r/R as its own word after ONE other short
  flag: `rm -f -r`, `rm -i -r`, `rm -d -r`, `rm -f -R`.
- `*rm*--recursive*`: `--recursive` anywhere after `rm`, closing
  `rm --force --recursive x` and `rm --recursive --force x`; subsumes the
  old adjacent-only `*rm --recursive*` (kept).
- `* -delete*`: `find . -name x -delete`, `find . -delete`, `bfs … -delete`.
  Chose the `-delete` token alone (any finder spelling) rather than requiring
  the word `find` first.
- `find . -exec rm -rf {} +` was ALREADY denied by the existing `*rm -rf*` —
  verified in the table, no new pattern needed.
- `rm -d`: DECIDED ALLOWED. It deletes empty directories only (non-recursive
  by definition); the task blessed that and blocking it would break ordinary
  scratch-dir cleanup. Recorded in the config comment too.
- Whole-line cost, same trade as PR #198 and now documented in AGENTS.md:
  a command that merely MENTIONS a denied spelling inside a string (e.g.
  `grep -rn "rm -rf" src`) is refused too.
- Known residual gaps (pattern matching cannot be exhaustive; these cost a
  permission prompt, not safety): three-or-more split flag words
  (`rm -v -f -r x`), and unambiguous long-option abbreviations
  (`rm --re x` — GNU rm accepts `--re` for `--recursive`). Left alone
  deliberately; chasing them would need broad tokens like `*--re*` that
  refuse far more than recursive deletes.
