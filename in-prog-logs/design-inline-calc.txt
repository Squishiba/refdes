D1. Results are stored in the file text and verified by check/build.
    Vout = 0.8 V*(1+Rtop/Rbot) = 4.436 V: the "= 4.436 V" is real text the
    editor (or a fill command) writes. If inputs change later, check/build report
    the stale number ("says 4.436 V, now computes 4.52 V") instead of silently
    changing it.
    (The design doc expresses this owner sketch as
    `Vout := 0.8 V*(1+Rtop/Rbot) = 4.436 V` under the grammar in §3.2.)
D2. The preview pane stays, as an optional "as published" view.
D3. No code execution. The existing restricted calc evaluator (src/refdes/calc.py)
    is the only evaluator. The editor gets live results from refdes serve (which
    already runs calc for the preview), never from a JavaScript copy of the
    evaluator.

Counted-spans methodology
-------------------------
The 39-span figure in §3.1/Q1 was produced by this command (run in the project
venv from the repository root):

```bash
python - <<'PY'
import re
from pathlib import Path

root = Path('.')

def strip_fenced(text: str) -> str:
    lines = text.splitlines(keepends=True)
    out = []
    in_fence = False
    fence_marker = None
    for line in lines:
        m = re.match(r'^(```+|~~~+)', line)
        if m:
            if not in_fence:
                in_fence = True
                fence_marker = m.group(1)
            elif line.startswith(fence_marker):
                in_fence = False
                fence_marker = None
            continue
        if not in_fence:
            out.append(line)
    return ''.join(out)

pattern = re.compile(r'`([^`\n]*?)`')
name_eq = re.compile(r'^[A-Za-z_][A-Za-z0-9_]* = [^=]+$')

for sub, exclude_this_doc in [('docs', True), ('tests', False)]:
    total = 0
    examples = []
    for p in sorted((root / sub).rglob('*.md')):
        if exclude_this_doc and p.name == 'inline-calc.md' and 'design' in p.parts:
            continue
        txt = p.read_text(encoding='utf-8', errors='ignore')
        txt = strip_fenced(txt)
        for m in pattern.finditer(txt):
            content = m.group(1)
            if name_eq.match(content):
                total += 1
                if len(examples) < 5:
                    examples.append((str(p.relative_to(root)), content))
    print(f'--- {sub}: {total} ---')
    for path, content in examples:
        print(f'{path}: `{content}`')
PY
```

Difficulties / choices
----------------------
- The write tool failed on large JSON payloads containing triple backticks and
  quotes, so the design doc and this log were written via Python scripts in
  bash. This is a tooling workaround, not a content change.
- Deciding how to handle stale results in sealed entries required checking the
  current reseal state; history-backed resealing is still pending, so the gate
  excludes sealed items.
- The grammar had to be extended carefully so that `? where Vout = 3.3 V` does
  not treat the constraint `=` as a stored result.
- Requiring `:=` as the trigger means anonymous inline evaluation is not
  supported. The trade-off is justified by the 39 existing `NAME = value` spans
  that would otherwise be misclassified.
- The E-series tie-break could have gone either way depending on whether the
  application cares more about overshoot or undershoot; the doc picks the common
  "do not undershoot a supply rail" rule and still shows both candidates.
- Keeping the solve bracket optional in the grammar while requiring it
  semantically is slightly unusual, but it lets the build report a clear error
  ("missing bracket") instead of silently treating a malformed solve span as
  ordinary code.
- This log is now committed without amending so that its commit citations remain
  stable.
