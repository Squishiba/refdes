Owner decisions (verbatim from the task brief, recorded here for durable citation)
---------------------------------------------------------------------------------
D1. Results are stored in the file text and verified by check/build.
    Vout = 0.8 V*(1+Rtop/Rbot) = 4.436 V: the "= 4.436 V" is real text the
    editor (or a fill command) writes. If inputs change later, check/build report
    the stale number ("says 4.436 V, now computes 4.52 V") instead of silently
    changing it.
D2. The preview pane stays, as an optional "as published" view.
D3. No code execution. The existing restricted calc evaluator (src/refdes/calc.py)
    is the only evaluator. The editor gets live results from refdes serve (which
    already runs calc for the preview), never from a JavaScript copy of the
    evaluator.

Fix round (chunk 1 review, 84f391c)
-----------------------------------
Findings addressed:
1. Added an explicit trigger rule in §3.1: a code span is inline math only if
   its content matches the §3.2 grammar (contains `:=` or trailing `= <quantity>`);
   ordinary spans like `Rtop/Rbot` and `foo()` are untouched. Q1 is now about
   the trigger rule, with a mandatory-prefix alternative.
2. Fixed the D1 example to use `:=` and noted that D1's wording was the owner's
   sketch, now expressed in the grammar.
3. Changed `valid_if` from general boolean expressions to comparison
   constraints (`expression op quantity`) using the existing `Limit.check` /
   `parse_limit` logic. No general comparison operators are added to calc; no
   control flow.
4. Made §7.1/§7.2 consistent with Q9's default: explicit `from .. to ..`
   bracket is required.
5. Gave P1 an honest dependency list: Q1, Q2, Q4-Q7.
6. Cited owner decisions durably in this log (above) and in PR #250; removed
   the `.scratch/task/TASK.txt` citation from the design doc.

Orchestrator recommendation changes applied:
- Q5 / §4.4: stale stored results are warnings by default; they become a
  release-gate failure via a new `stale_inline_results` rule (default
  `{release: true, revision: false}`).
- Q8 / §6.3: default is live auto-update while typing using a native
  text-insertion path (`document.execCommand('insertText')` or `setRangeText`)
  to preserve browser undo; a browser test is required before P2 ships. The
  explicit Fill button remains the fallback.
