Findings worth recording (all re-read at the cited lines, not from memory):

1. The editor has no way to write `tasks:` at all. `tasks` is in
   NON_SCALAR_FIELD_TYPES (src/refdes/model.py:198-200), the editor model
   reports the field "collections are not editable here"
   (src/refdes/serve/api.py:213), `set_field` refuses a collection (api.py:508),
   patcher.SetField is "one direct scalar field" (src/refdes/patcher.py:127),
   and creation emits scalar fields only (src/refdes/serve/edit.py:1533-1551).
   The comment at src/refdes/build.py:339-341 is about something else: a
   non-list `tasks:` "is the loader's error -- `_reject_scalar_collection`
   owns that keystroke", i.e. parse._reject_scalar_collection
   (src/refdes/parse.py:741) is the one that reports that malformed shape. It
   says nothing about the editor. (The first draft read the comment as naming
   the editor; it does not -- corrected in fix round 1 below.) The gap above
   is the gap W5b's core phase fills, and it is why the plan does not propose
   reusing the existing /edit/ save op.

2. An editor save does not write the `followed` history event. edit.py loads
   with write=False (src/refdes/serve/edit.py:340) and nothing under
   src/refdes/serve/ calls history.capture_followed or links.anchor_follows
   (the `capture` hits in serve/upload.py are the unrelated "would capture a
   bare-name reference" lint). The capture point is links.anchor_follows
   (links.py:770-815, reached from loader.load_tree at loader.py:143 with the
   load's own write flag), so a continuation written by the browser captures its
   predecessor on the next writable load. living-notes.md:185-188 asks for entry
   + event in one transaction. Raised as Q2's explicit sub-question rather than
   quietly decided.

3. Creation has no revision check: CreateRequest has no expected_revision
   (edit.py:1013-1038), so Q3 ("the tip moved while the draft was open") has no
   mechanism on the create path today. Said so in the doc instead of assuming a
   compare exists.

4. The draft mechanism exists and is real, but its shape does not fit:
   src/refdes/serve/static/drafts.js holds {revision, fields, body, pins,
   links} per item handle, memory + sessionStorage, beforeunload. Keyed by
   item, not by tip, and no task rows -- so the plan reuses its *lifetime rules*
   and adds a sibling draft kind, rather than reusing the draft shape.

5. The serve-only seam for anything that writes is the response decoration, not
   a template flag: serve/server.py:_decorate (:738-776) injects the toolbar and
   _reload_probe into the HTTP response only. Note `draft_build`
   (src/refdes/render.py:976) is NOT that discriminator -- it means
   `build --dry-run`/seal-skipping, and the preview render passes draft=True for
   every preview page, so a template test on it would not keep a control out of
   a plain `refdes build`.

6. Vocabulary drift worth flagging: living-notes.md §5 proposed
   `on_change: log` for `tasks:`; the shipped standard says
   `on_change: timeline`
   (src/refdes/standards/hardware/v3/base.yaml:302). The page cites the shipped
   spelling and names the drift.
