## Test added

`tests/test_markdown_parser_cache.py`, 5 tests, no timing assertions:

1. `test_a_build_constructs_one_markdown_parser_not_one_per_item` — patches
   `build.MarkdownIt` with a counting subclass and asserts a 12-item build
   constructs exactly 1. This is the test that would have caught the bug.
2. `test_the_hash_pass_and_the_render_pass_share_one_instance` — `compute_hashes`
   then `render_bodies`/`render_pages` must not construct a second one, and
   `_markdown_parser()` must keep handing back the same object. Pins the property
   the factory's docstring calls load-bearing (hash pass and render pass seeing
   the same image set), which is the part a "just cache it locally per function"
   refactor would break while still passing test 1.
3. `test_a_build_does_not_reconfigure_the_shared_parser` — `md.options` and the
   core/block/inline rule chains before and after a build must match, and
   `html`/`linkify` must still be False. Sharing a mutable object is only safe
   while nothing calls `configure`/`enable`/`disable`/`use`; this is the tripwire.
4. `test_each_thread_gets_its_own_parser` — three threads get three instances,
   repeat calls in one thread get one. Pins the `threading.local` decision (a bare
   module global would pass 1-3 and fail this).
5. `test_the_shared_parser_renders_what_the_per_item_one_did` — the config itself
   through the shared instance: GFM table renders, `<s>` does not appear, the
   resolved and URL-scheme images both emit `<img>` (2 total), the code-fenced one
   stays literal text.

Gotcha worth recording: the cache is thread-local and outlives a test, so a count
taken with a warm cache is 0 and passes any "not too many parsers" assertion
vacuously — including against the sabotaged code. Every counting test therefore
resets `build._MD_LOCAL.markdown_it = None` through `monkeypatch` first
(`_cold_cache`). That is the one thing about this test that could have silently
been worthless.

Sabotage check, run for real: with `_image_inputs_hash_value` reverted to a
literal per-item `MarkdownIt(...)`, tests 1 and 2 fail (12 constructions for 12
items, with the message naming `_markdown_parser`), tests 3-5 still pass — the
correct split, since 3-5 describe behavior the bug never changed. Fix restored via
`git checkout -- src/refdes/build.py`; `git status` shows build.py clean, and
`grep -c "md = _markdown_parser()" src/refdes/build.py` is back to 3.
