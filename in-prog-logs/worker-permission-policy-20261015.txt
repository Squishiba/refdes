FIX ROUND (2026-10-18, security review of this PR):
The review found the classifier decided on metadata (exact filepath,
command text) while ignoring request.input.patterns -- the scope actually
released on allow. A metadata filepath equal to the exact PROGRESS.md file
could approve a wildcard directory request (.scratch/*); safe command text
same. Fixed by making the scope the whole policy:

- classifier.ts rewritten: gates = provider/kind/name, identity
  (parentAgentId in file-backed allowlist, or title starts "Review PR " --
  title verified present on hook agent payload, daemon
  plugins/lifecycle/index.js), and scope: patterns must be a non-empty
  string array, every entry absolute, no ".." segment, inside one of three
  roots (this project's worktrees 16msma8v, the checkout, venv-refdes) at a
  segment boundary. ALL patterns must pass; fail-closed on everything else.
  Metadata cases retired: root allowlist subsumes the progress-file case;
  command text is no longer an approval key (case 2 kept only as "patterns
  pass"), so fewer approved shapes (exactly one).
- Parents from ~/.paseo/plugin-settings/refdes-worker-permissions/parents.json
  (README documents; env REFDES_WORKER_PERMISSIONS_PARENTS_FILE / PASEO_HOME
  overrides; absent/malformed = empty list = nothing approved). Claude
  f3993852... primary, Sol d86b9967... backup; parents.example.json ships.
- Adapter re-verified in the INSTALLED daemon (opencode-agent.js,
