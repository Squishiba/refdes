What was done
-------------
- model.py: SEALING_BUILD / SEALING_HISTORY / SEALING_MODES; ItemType.sealing
  (default "build").
- schema.py: parses `sealing:`; unknown value -> SchemaError; `history` on a
  non-append_only type -> SchemaError.
- configcheck.py: `sealing` accepted as a types: key, value validated.
- standards.py: Liskov guard -- a subtype may not declare `sealing: history`
  under an append-only parent that keeps the build lock (mirrors the existing
  append_only guard). Overlaying the type itself is how a project opts in.
- seal.py:
  - history_backed(); append_only_items()/_boards_in_play() take an optional
    sealing filter; verify() only seals/hash-checks/reseals/migrates
    build-sealed types.
  - is_sealed() is False for history-backed types. This one predicate is what
    links.plan_follows_freeze's refusal, serve/edit.py, serve/upload.py,
    serve/api.py and calc_rewrite/build's retired-unit leniency all read, so
    they all agree: a history-backed entry is not locked anywhere.
  - _verify_history_backed(): read-only. `--reseal` prints the Q2 message
    once per history-backed type; a legacy seal record naming the entry under
    a different key is still an ERROR (key corruption is not an edit).
  - _report_deleted(): an orphan record is classified by display-id prefix
    (falls back to all append-only types); only when every candidate type is
    history-backed is it a WARNING naming the record, key and seal file --
    any doubt keeps today's error. Never dropped by --reseal. And a board's
    seal file is now only re-saved under --reseal when a record was actually
    dropped (before, any orphan in scope re-saved it -- harmless for
    build-only projects since every orphan was dropped, but it would have
    rewritten a legacy file whose orphans were all history-backed).
- links.py: comment only; refusal logic and warning text unchanged.
- revise.py: _carry_forward_seals skips history-backed entries. NOT in the
  plan's file list, but it is a seal-file writer, and H5 promises legacy
  files are never rewritten; with no lock left there is nothing to carry.
- cli.py audit: history-backed rows in "Append-only entries edited after
  sealing" get "(legacy seal: recorded hash only; original content was not
  captured)"; new sibling section "Entries edited after captured:". --reseal
  help text mentions history-backed types.
- base.yaml: untouched (log stays append_only, sealing defaults to build).
- tests/fixtures/hardware3_*resolved.json: the oracle dumps every ItemType
  field, so each type gained `"sealing": "build"` -- added mechanically,
  verified to be the only change; it also pins that no hardware@3 type is
  history-backed.
- Docs: design-log.md "History-backed types" subsection; schema-reference.md
  row + extends notes; cli-reference.md --reseal row. Changelog fragment
  changelog.d/history-backed-sealing.added.md.
