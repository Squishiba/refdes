## Policy decided

"Already covered" is git's question, so in a repository ask git:
`git check-ignore --no-index -v -- <path> <parent-dir>`. True addressed =
the winning match's SOURCE is the project's own `.gitignore` (ignore match
= covered; negation match = intent to track, must not be out-ranked). The
parent directory is asked in the same call because `.vscode/` + `!.vscode/`
puts the intent on the directory, and the file itself matches nothing.
Matches from `.git/info/exclude`, a global `core.excludesFile`, a parent
project's `.gitignore`, or a deeper nested `.gitignore` are NOT the
project's own position -> init appends (its file then wins by depth for
paths under the project). `--no-index` so staged state never colors the
answer. Not a git repo / no git binary / git fails / timeout -> `None` ->
literal fallback (kept, widened with basename and one-level-glob spellings,
`.vscode/*`-style and `.vscode/**`-style, all of which genuinely cover the
path). No `.gitignore` at all: unchanged (init writes a fresh file, no
append, no git consulted). Preflight `_refuse_unwritable_gitignore` uses
the same function, so the #231 read-only refusal behavior is preserved for
files that genuinely miss an entry (a read-only gitignore with the negation
covering vscode still gets refused for the missing `.refdes/` lines, as
before).

## Empirical git semantics recorded (scratch probes, git 2.47.3)

- `check-ignore -v` exits 0 on ANY winning match including negations (the
  `!` prefix in the output pattern marks track-intent), 1 on no match.
- In a NON-repo directory it exits 1 (not 128!) -> repo membership must be
  probed separately: `rev-parse --show-toplevel` (rc!=0 -> fall back).
- Source paths are reported relative to the repo TOPLEVEL, not cwd
  (`hardware/board-a/.gitignore:...` when run from the project subdir) ->
  compare with relpath(target/.gitignore, toplevel), plus a realpath
  variant for symlinked temp dirs (macOS /var).
- git strips trailing CR from patterns; basename/glob/CRLF spellings all
  verified against real `git check-ignore`.
