## Item 1 — empty `--workspace` silently disables the filter (PR #286)

VERIFIED as still applying, reproduced in .scratch/ws-nits/proj (a fresh
`item_layout: workspace` project with platform/product-a):
- `refdes ls --workspace ''` listed every item, exit 0.
- `refdes check --workspace ''` checked the whole project, exit 0.
- `refdes check --workspace nosuch` → named ERROR, exit 1 (the good posture).

Commands with `--workspace`: only `check` (cli.py ~431) and `ls` (cmd_ls
filter loop + argparse ~3032) — grepped `add_argument.*--workspace` and
`args.workspace` across src/.

Fix (cli.py):
- cmd_check: validation `if args.workspace and ...` → `if args.workspace is
  not None and ...`. `''` now flows into the existing named-error branch
  (difflib finds no hint for '').
- cmd_ls: new guard before the listing: `--workspace ''` records a project
  error naming the flag, prints all errors to stderr, returns 1 with NO
  listing (a full listing under an empty filter is the lie; ls's
  parse-error convention keeps the listing because there the listing is
  intact — here it answers the wrong question).
- Unknown *names* in ls deliberately unchanged: "no items match" exit 0 is
  ls's documented query posture for --type/--board/--workspace (its own help
  says so; test_ls_unknown_workspace_matches_nothing_rather_than_erroring
  pins it as a "deliberate asymmetry"). Making ls error on typos is a design
  decision beyond this nit — noted in the PR body, left alone.

Docs: docs/cli-reference.md — the ls section claimed `--workspace ''` "is an
empty flag value, not a wildcard — it filters nothing and lists everything"
(now false; rewritten to the refusal) and "`--workspace anything` is 'no
items match'" on a no-registry project (the empty value is the exception;
reworded to `<name>`). docs/workspaces.md "blank is not a name you can pass
to the filter" stays true, untouched.

Tests (tests/test_workspaces.py): 3 new — ls-empty named error (+ no listing
on stdout, registry project), check-empty named error, ls-empty refused on a
NO-registry project. Updated the test that pinned the old no-op
(test_ls_shows_an_item_in_no_workspace_as_a_blank_and_never_matches_it:
dropped the `--workspace ''` lists-everything assertion, updated docstring).

Sabotage: (1) reverted the check truthiness fix →
test_check_empty_workspace_flag_is_a_named_error failed (0 == 1); restored.
(2) removed the ls guard → test_ls_empty_workspace_flag_is_a_named_error and
