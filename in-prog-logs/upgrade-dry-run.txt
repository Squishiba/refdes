## Design

- apply_standard_upgrade(project_root, to_version, dry_run=False): identical
  pre-flight refusals first (not-pinned / already-at-target raise SchemaError
  the same under dry-run, exit 2), then --dry-run runs the real chain on a
  copytree of the tree under tempfile.mkdtemp (ignoring _site/.git like the
  two existing simulation helpers) and discards it. The plan is the real
  run's own RevisionResults -- files, id changes, baselines/seals carried
  forward, stale prose, refusals -- so it cannot drift from the real engine.
  The real tree is never touched, keys are never minted to it, the pin never
  moves.
- CLI: --dry-run flag; --no-write now maps to dry-run (the refusal's own text
  justified itself by "it has no dry-run"; every sibling with --dry-run is
  forced onto it by --no-write -- keys adopt/restore, rename, calc-rewrite --
  and docs/cli-reference.md's --no-write table states exactly that convention:
  "commands with --dry-run report what would change"). Global --no-write help
  text and the cli-reference --no-write row move "standard upgrade" from the
  refuse list to the report list.
- Dry-run output: existing per-step "would change N file(s):" from
  _print_revision_result (same verb the rename/calc-rewrite dry runs use),
  a "standard.version: 2 -> 3 (would be bumped)" line per step, and
  baselines/seals lines ("baselines would be carried forward: ...") which
  _print_revision_result now prints under dry_run too (plain `revise
  --dry-run` is unaffected: its result carries none of those fields).
