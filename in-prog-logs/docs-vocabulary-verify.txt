Possible bugs (code-side text inside the generated block — NOT fixable in
docs; listed in PR body):
B1. `verifies` example (page 493-500, vocabulary.py:530-536) claims "Or
    from the requirement, under the inverse name -- same edge either way"
    and shows `verified_by: [TST-PWR-001]` on a requirement. Real build
    (probe1): ERROR "unknown field 'verified_by' on requirement -- did you
    mean the link 'governed_by'?". Inverse names are not authorable
    anywhere (no inverse handling in parse.py); they are computed
    backlinks. This also violates the intro's own "Every example is
    schema-true" claim.
B2. `body` reserved-key doc (page 733): "for types whose content is the
    statement itself it is the required field" — enforcement is a WARNING,
    not required-field error (build.py:298-303; base.yaml:56-58 says so
    explicitly, on purpose, so stubs can exist).
B3. `former_ids` doc (page 719): "Written by the engine when an id is
    re-minted, so old citations still resolve." probe5: `refdes rename`
    prefix REQ-PWR->REQ-PSU re-minted ids, wrote NO former_ids, and a bare
    reference to the old id ERRORS ("a bare reference cannot follow a
    rename"). former_ids is written by `refdes former-ids propose
    --confirm` (needs a stamped baseline) or by hand — opt-in, not
    automatic.
B4. `board` doc (page 778): "the first path segment under `items/` unless
    the item says otherwise" — only segments matching the `boards:`
    registry resolve; unregistered folder = warning + board unset
    (probe items/board-x/). With no registry at all every board is unset
    (repo's own refdes-project.yaml comment says so).
B5. `section` doc (page 825): "the section heading its entries file under
    on the item's page; in a Markdown marker block, the section a
    generated block belongs to." Actual semantics (parse.py:813-838,
    1634-1638): a section marker asserts the TYPE of every item after it
    until the next marker (stricter than defaults); the Markdown spelling
    is a `--- section: <type> ---` front-matter block. No
    item-page-heading, no "generated block" concept. The page's own
    example comment ("every item after it is a requirement") is correct;
    only the scope sentence is off.
