2026-10-03: Read in-prog-logs/write-inventory-for-locking.txt first. Tier A is item sources, .refdes/ids.yaml, and .refdes/keys-adopted.yaml. Existing serve/edit.py lock uses fcntl.flock on POSIX and msvcrt.locking on Windows.

Design: src/refdes/write_lock.py generalizes the existing stable .refdes/serve-write.lock path. An in-process RLock and thread-local depth make nested acquisition safe; the disk lock serializes processes. CLI acquires it before project load and holds it through command completion so key minting, reference expansion, ID planning, source edits, ledger save, and adoption-marker rewrite all share a snapshot. Serve edit uses the same lock for its final compare/write; serve creation holds it from load through file creation and ID reservation. Lock file is never unlinked. --no-write skips acquisition. A whole-tree read-only root skips lock creation and preserves ordinary write refusal handling.

Lock order: project in-process RLock -> project disk lock -> project read/plan -> Tier-A source/marker atomic replacements -> ID ledger atomic replacement. Serve's existing per-process editor lock is acquired before project lock. No path may acquire these in reverse. Nested project lock acquisitions are reentrant.

Atomic writes: textio.atomic_write_text uses same-directory mkstemp, original mode, flush/fsync, and os.replace, and checks read-only target/directory mode first. Applied to revise's FileRewrite writer/rollback and IDs' source and ledger writers. Output bytes remain the previous rendered text.
