## Step 1 — where former ids live (read, not guessed)

- `former_ids:` is an item field (`parse.py:721-723`), reserved
  (`parse.py:40`), and only ever *inferred* on request by
  `refdes former-ids propose` (`former_ids.py`), which writes it back into the
  source (`former_ids.py:204-240`).
- `project.former_ids` is the old-id -> current-id map, populated by
  `ids.collect_former_ids` (`ids.py:338-379`), called from
  `build.validate_former_ids` (`build.py:426-438`), which `build.build` runs at
  `build.py:2979`. Collision rules live there and matter for part 1 below: a
  former id that names a still-live id is a hard *error* and is deliberately
  left out of `project.former_ids` (`ids.py:361-369`).
- `render.items_json` already carries `former_ids` per item
  (`render.py:661`), so the VS Code extension's index rows already have it.
- The prose "(formerly X)" marker is `build.py:2326-2344`.

## Step 3 — the change, in four parts

### 3a. `refdes ls OLD-ID` (`cli.py: cmd_ls`, `cli.py` parser help)

`ls` takes one optional positional: `query`, `nargs="*"`, joined with spaces and
lowercased (`cli.py:644` on this branch). Unchanged. The **haystack** gained one
more source: each item's `former_ids:`, under the identical
case-insensitive substring rule as id/title/tags. Matching is read off
`item.former_ids` rather than `project.former_ids` on purpose — the map
deliberately omits an entry that collides with a live id
(`ids.py:361-369`), and the reuse case below needs to *see* that entry in order
to report it.

Marker, printed only where the query actually met a former id, so `ls` and
`ls NEED-PWR-001` print exactly what they printed before:

    NEED-PWR-001  need  The 3V3 rail shall supply 1.2 A continuous. (formerly REQ-PWR-001)

Reuse case: a retired id that is a live id again is the live item's id, so the
live item is the row, and the former holder is named in a note under the table
(`_print_reuse_note`) — the listing would otherwise read as though the retired
id had never existed. That combination is already a build error
(`refdes check` says "former_ids: 'REQ-PWR-001' is still a live item id"),
verified above; the note points at `refdes check` rather than duplicating the
diagnostic.

Exit codes are untouched: `ls` still exits 1 only for items files that failed
to parse. `project.errors` is a property returning a fresh list
(`model.py:1009`), so `load_errors` is a pre-build snapshot and build errors
never set `ls`'s exit code — before this change or after it.

### 3b. The item page (`templates/item.html.j2`)

`<p class="small muted">formerly known as <code>REQ-PWR-001</code></p>` between
`.item-head` and `.item-title`. **No stylesheet change**: `test_style_tokens.py`
pins the set of selectors (`test_no_selectors_added_or_removed`) and the
resolved declaration set, so a new `.item-former` class would fail that test
rather than land. Existing classes only.

### 3c. Hover card (`render.preview_payload`, `templates/assets/app.js`)

`preview_payload` gained `"former_ids"` **only when the item has some** (the
same "absent key, not null" convention `items_json` uses for `boards`), so a
project that records no renames keeps byte-identical preview data.
`app.js`'s `build()` pushes a `<dt>formerly known as</dt><dd>…</dd>` row onto
the card's existing field list, which is what styles it — again no new
selector.

### 3d. VS Code hover (`serve/api.py _item_view`, `editors/vscode/extension.js`)

Contained, so done. `_item_view` returns `"former_ids": list(item.former_ids)`;
`itemMarkdown` prints `_formerly known as …_`, preferring `view.former_ids` and
falling back to the index row's (which `render.items_json` has always carried),
so the fact survives with no `refdes serve` running — the same
"one hover, one answer" rule the coverage stage already follows.

Deliberately **not** done: making the editor hover fire on a *retired* id. The
hover is driven by `getWordRangeAtPosition(ID_RE)` + `itemsById().get(id)`, so
resolving a stale id means returning a *different* item's card for a word that
no longer names it, without saying so. That is a design decision (same family as
"never silently redirect a reader following an old id"), not a lookup tweak, and
the task scoped this to "hovering an id shows formerly known as". Flagged here
rather than done quietly.
