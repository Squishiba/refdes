## The claim, and what was actually wrong

`run_checks` gated its key diagnostics on `"@" in target_id`, while
`resolve_links` gates on `"@" in target_id or _is_bare_key_token(target_id)`.
So the same key-shaped token, written without its display half, took different
branches in the two places:

- `checks: [{value, against: <bare key>}]` -> `_dangling_bare_message`
  ("... which does not exist -- a typo ... write the item's new id here")
- the same token in a `links:` target -> `_unknown_key_message`
  ("points at key ..., which no item declares ... `refdes keys restore`")
- and, pre-fix, a *corrupt* bare key in `against:` read as a typo instead of
  the corruption report that a link target gets.

`docs/design/keys.md` Layer 3 says the opposite ("The same diagnostic serves
structured links, `checks: against:`, and cross-item calc references", ~1016).
So the docs were right and the code was wrong; the fix is in the code.

## The change

`src/refdes/build.py`, `run_checks` only (the entry loop, ~1689-1740):
`bare_key = _is_bare_key_token(target_id)` is computed once and both gates
become `"@" in target_id or bare_key` -- the Layer-1 malformed check (now
including a corrupt bare key, with the label clause only when there is a
label), and the Layer-3 choice between `_unknown_key_message` and
`_dangling_bare_message`. For the bare-key failure `CheckResult.detail` reads
`key '...' does not resolve` instead of `'...' does not exist`, matching the
composite case. This mirrors, rather than re-implements, `resolve_links`
(build.py:794-821), the citation `item:` check (build.py:439) and the calc
resolver (build.py:1316), all of which already carried `_is_bare_key_token`.
`grep -n '"@" in\|_is_bare_key_token' src/refdes/build.py` now shows no
key-diagnostic gate left on `@` alone.

Tests: `tests/test_checks_keys.py`, new section after the Layer 1/3 tests,
using the hardware standard because the comparison needs a real declared link
type (`CHECKS_SCHEMA` in that file declares no `links:` at all):

- `test_undeclared_bare_key_in_against_gets_the_same_layer3_text_as_a_link`
  -- pins `check == link.replace(...)` (one wording, pointer phrase aside), and
  the absence of the dangling dead-end phrases.
- `test_malformed_bare_key_in_against_is_corruption_not_a_typo` -- same, for
  the corruption report.

- `test_dangling_bare_display_id_in_against_keeps_the_dangling_message` -- a
  hyphenated id is not key-shaped, so the widened gate must not pull an
