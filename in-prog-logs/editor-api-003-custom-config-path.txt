Finding (shared main in-prog-logs/current-main-resweep-editor-api.tsv row 003)
--------------------------------------------------------------------------------
`refdes -c custom-project.yaml check` succeeds; a server launched with the
custom config serves reads, but POST edit and create rebuild
`os.path.join(root, 'refdes-project.yaml')` and 422-refuse because the
marker is absent.

Trace
-----
- cli.py:2738 defines global `-c/--config`; cmd_serve (cli.py:547) passes
  args.config to EditorApp; EditorApp (server.py:466) passes it to
  ProjectState; ProjectState._build loads through it (state.py). Reads work.
- api.py `_apply_edit` (:538) and `_create_item` (:706) passed only
  `project.root`; edit.py `apply_edit` (:307) and `create_item` (:1064)
  rebuilt `os.path.join(root, CONFIG_NAME)` with CONFIG_NAME hardcoded.
  Every loader in the locked section (before snapshot, overlay gate, create
  plan) then read a file that does not exist.
- Watcher: state.project_inputs added `os.path.join(root, name)` for the two
  hardcoded names, so a custom config file was never in the watched/revision
  set: editing it moved no revision, and the poller could not reload on it.
- sources/upload/preview routes write no project-config path; nothing else
  rebuilds the marker name in serve/ (grep `refdes-project.yaml` in
  src/refdes/serve/ hits only the two edit.py joins + a --token-file doc
  line).

Fix (threading, no cwd reliance, no default-behavior change)
-------------------------------------------------------------
- state.py: `ProjectState.__init__` abspaths the configured path once at
  launch (same basis the loader uses; serve never moves cwd).
  `project_inputs(project, config_path=None)` names the configured settings
  file in the watched/revision set; `refdes-schema.yaml` stays a fixed name
  beside root (that is how `_load_schema_overlay` resolves it). `_build`,
  `pending_signature`, and `refresh` thread the path.
- edit.py: `apply_edit(project_root, request, config_path=None)` and
  `create_item(project_root, request, config_path=None)`; omitted -> the
  default marker beside root, exactly the old behavior. All locked-section
  loads already take `config`, so the one line at each entry point covers
  before-snapshot, overlay gate, delta gate, and create plan.
- api.py: both write routes pass `config_path=app.state.config_path`.
- Concurrency untouched: lock keys stay `os.path.normcase(os.path.abspath
  (project_root))` (== the config's directory), write-lock ordering,
  accept-pin/landed-body windows, and `_atomic_replace` all unchanged --
  no entry into the #241/#244/#253 lanes.
