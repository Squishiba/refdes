# malformed-lockfile-diagnostic — progress log

Task: F5 from `in-prog-logs/remote-fetch-exercise.md`. A malformed
`.refdes/citations.yaml` gives a raw `ValueError` traceback out of `fetch` and
`check`. Make every corruption shape give a diagnostic instead, named by file
(and line where available), refusing to overwrite a corrupt lockfile with a
`fetch` that cannot read the pins it would lose.

Branch `malformed-lockfile-diagnostic` off current main (`ae95a29`). Wrapper for
every CLI run below:

    PYTHONPATH=/home/jorb/.paseo/worktrees/16msma8v/malformed-lockfile-diagnostic/src \
      python -m refdes.cli ...

(the `refdes` on PATH is a broken editable install pointing at another worktree.)

## Where the readers are (grepped `src/refdes/`)

`citations.load_lockfile()` (`src/refdes/citations.py:414`) is the single reader.
Call sites:

- `src/refdes/citations.py:669`  — `verify()` (check/build/release gates)
- `src/refdes/citations.py:1009` — a `source()` value lookup
- `src/refdes/citations.py:1353` — `fetch_all()`
- `src/refdes/citations.py:1566` — `check --refresh` drift scan
- `src/refdes/build.py:1181`, `src/refdes/build.py:1335` — `run_calcs`, which is
  why plain `check`/`build`/`audit` traceback too (they all call `build()`)
- `src/refdes/serve/sources.py:93` — the editor's source listing
- `src/refdes/serve/edit.py:538` — the editor's accept-pins diff

`load_lockfile` is `dict(data.get("citations") or {})` — anything that is not a
mapping is handed straight to `dict()`, which is the F5 traceback.

- [x] Split the reader in two, because the writers and the readers need opposite
      answers from a broken file:
      - `load_lockfile(project)` -- strict, raises `citations.LockfileError`.
        Used by every writer: `citations.fetch_all`, `cli.cmd_fetch`, and
        `serve/edit._accept_pins` (which returns `(None, str(exc))`, so the
        editor refuses the edit instead of rewriting a lockfile it could not
        read). A missing file is still `{}`: this project has pinned nothing,
        which is ordinary.
      - `read_lockfile(project)` -- returns `(records, problem)`, reports one
        ERROR diagnostic naming `.refdes/citations.yaml` and the line, memoized on
        `project._lockfile_reported` so a build that reads the file twice says it
        once, and returns `{}`. Used by `verify()`, `refresh()`,
        `_extract_source_values`, `build.run_calcs`, and `serve/sources._lockfile`
        (which raises `SourceRefusal`).

      The `{}` a reader returns must not read downstream as "every citation is
      unpinned" -- that would turn one unreadable file into a page of invented
      errors -- so the no-cascade behaviour is asserted directly.

- [x] Added the shape the F5 survey did not name but that loses a pin with *no*
      word at all: a repeated key. YAML resolves a repeated key to the last one
      and says nothing, so two sound records for one cited path read as one, and
      `fetch` rewrites from the loaded mapping -- the loser is dropped forever
      with nothing in the tree to notice. `_duplicate_key()` walks the *composed*
      node tree (loading is where the repeat is lost), reports the first repeat in
      any mapping with both lines, and says whether anything is actually lost
      (`_node_equal`, structural, with a visited set and a depth bound: an alias
      can make a node its own ancestor, and a report that hangs on a corrupt file
      is F5 wearing a different hat). Two occurrences on one line read "twice on
      line N" rather than "(lines N and N)", the way parse.py words the same shape
      in item front matter.

- [x] `audit` was printing nothing at all for a corrupt lockfile, and exiting 0:
