The bug
-------
A 5000-digit page/row/token query parameter made the handler die with an uncaught
ValueError ("Exceeds the limit (4300 digits) for integer string conversion") raised by
int() itself, so the client got no response at all (RemoteDisconnected):

- GET /api/item/<ref>/sources/propose with page|row|token oversized — serve/sources.py:856,
  _pdf_proposal's isascii()/isdigit() guard bounded nothing, int() raised.
- GET /api/item/<ref>/sources/page?page=<5000 digits> — citations.py:311 page_number's
  int(), and the call at api.py:403 sits outside the SourceRefusal try at api.py:410.

Controls (same params, page=abc) correctly returned 422 (propose, via the SourceRefusal ->
_refused path) and 400 (page route, the "page must be a positive integer" check).

The fix
-------
The bound is the grammar's own, not the interpreter's. citations.MAX_PAGE_DIGITS = 64,
documented at its definition (src/refdes/citations.py): the interpreter's int-conversion
limit is 4300 by default, can be disabled (0), and the smallest non-zero value it accepts
is 640 — verified on this interpreter (3.13.5): sys.set_int_max_str_digits(64) raises
"maxdigits must be 0 or larger than 640", and PYTHONINTMAXSTRDIGITS=640 is accepted.
64 digits therefore converts under every interpreter setting (64 < 640 < 4300), and no
page of any document has sixty-five digits, so a longer run simply is not a coordinate:

- citations.page_number returns None for a digit run longer than MAX_PAGE_DIGITS, which
  makes the page route return its documented 400 at api.py:409 without touching the route.
  Same effect (no crash, declaration error) for a 5000-digit `page:` in a YAML citation:
  probed `refdes check` -> "page: ... is not a page number -- page: must be a positive
  integer, counted from 1", exit 1, no traceback.
- serve/sources._pdf_proposal checks len(text) > citations_mod.MAX_PAGE_DIGITS inside the
  existing digit/minimum loop, so an oversized page/row/token raises SourceRefusal with
  the route's own "X must be an integer >= N for a PDF pick" -> documented 422. That also
  covers the POST /edit accept path, which revalidates through the same propose_payload
  (edit.py:654 already maps SourceRefusal to the 422 refusal).

The accepted grammar itself is unchanged below the bound: "2", "02" and friends still
parse (page_number('2')==2, page_number('02')==2 probed), 19-digit and 64-digit values
still flow through as integers and still get the reader's out-of-range refusal (probed:
page of 19 digits -> 422 "page 999... is not in this document", both routes), only runs
over 64 digits flip from crash to refusal.
