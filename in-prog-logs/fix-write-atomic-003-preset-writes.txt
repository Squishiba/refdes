The change
----------
src/refdes/scaffold.py — three writes moved from textio.write_text to
textio.atomic_write_text (existing helper from PR #162: same-directory
mkstemp temp, fsync, chmod to the old file's mode when the target exists,
os.replace, temp unlinked in `finally` on any failure):
  - add_preset, refdes-project.yaml write
  - remove_preset, the .scratch simulation copy
  - remove_preset, the real refdes-project.yaml write
Comments at each site updated to say why. No refusal semantics changed:
atomic_write_text's explicit read-only file/dir checks raise PermissionError
(a subclass of OSError), so the existing `except OSError -> Refused` paths
and their messages/exit-2 codes are preserved — including the
"(read-only tree?)" wording the docs table and
tests/test_readonly_explicit_writes.py pin. Scratch-copy mode/layout: the
temp is created in the same directory and renamed on, so the config's inode
context (directory, mode via chmod) is preserved for the real writes; the
scratch copy is ephemeral (read by the simulation, deleted in `finally`) and
inherits no mode expectation.

Difficulties
------------
  - The shared-venv editable install points at /home/jorb/work/refdes, so
    every CLI probe needed PYTHONPATH=<worktree>/src; the probe self-reports
    refdes.scaffold.__file__ to make that checkable rather than assumed.
  - Writing the fault injection so it fires only on the intended temp:
    os.write monkeypatching does not catch buffered text writes, so the
    injection aims at os.fsync (pre-rename) and at a thin os.fdopen proxy
    whose write() raises ENOSPC (mid-write) — both aimed by the mkstemp
    temp's recorded fd. The first proxy draft forgot __enter__/__exit__ and
    broke `with os.fdopen(...)`; fixed.
  - Deciding the scratch copy's mode semantics: atomic_write_text copies the
    target's mode only when the target exists, and a new scratch temp lands
    0600 (mkstemp default) rather than the old umask default. Accepted as
    correct-not-identical: the scratch lives microseconds, is read by the
    same process that wrote it, and is deleted in `finally`; the real config
    writes (where mode matters) all preserve it. Flagging PERM-OWNER-002/003
    in the TSV as the separate open findings that cover new-file mode and
    ownership generally — deliberately not folded into this fix.
