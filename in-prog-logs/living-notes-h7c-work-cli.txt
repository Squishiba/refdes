DESIGN DECISIONS (made up front; STOP-rule items marked (OWQ) also go under "Open wording questions" in the PR body):

1. Command shape. `refdes work` takes no ref (it is project-wide). Flags: --json, --as-of DATE (same flag/semantics as `refdes thread`). Reads build state (coverage/checks/blocked/citations) via build(seal_write=False, reseal=False) like index/ls/thread; never touches the network (drift is citations.refresh under check --refresh only — left out, stated in docs + here). Writes nothing but the load's own key minting/expansions.

2. Structure = §5's two binding-rule groups. (a) Authored open tasks, per thread / per tip, numbered within each block. (b) A clearly labelled `Derived (self-closing):` section, unnumbered, no checkbox, self-closing. (Binding rule 1: separate groups, separate numbering, derived never written back.)

3. Authored group shows OPEN tasks only (it is a worklist). A tip with no open task contributes no block. An ambiguous task fold ("task reconciliation required") prints its header line so the author's own error is not silently dropped (it has no list to show). Reuses thread's `Thread:` header, `Tasks at tip:` / `Tasks at <tip>:` headings and task row format.

4. Derived kinds produced offline (reuse existing producers, add nothing to the fold/coverage/check machinery):
   - uncovered + unverified active requirements -> lifecycle._rule_uncovered_requirements / _rule_unverified_requirements (already in threads._derived_problems)
   - failing checks -> item.checks (build.run_checks)
   - blocked-by cascades + stale blockers -> blocked.by_item (blocked.resolve)
   - unpinned citations / missing kept copies -> item.citations states {unpinned, cache_missing} (citations.verify; == _rule_unpinned_citations / _rule_missing_kept_copies)
   - proposed/on-hold verdicts -> read from the projection's branch verdict (chains.fold_field_at_tip status fold); a new derived "verdict" row
   - forked threads -> threads_projection view["forked"]/["tips"]; a new derived "fork" row
   Remote citation drift: NOT produced (networked). Stated in docs + this log.

5. "If the projection lacks something, add it to the projection (with a test), not to the CLI." threads_projection is per-thread scoped (derived per thread = members + one hop). A PROJECT-WIDE worklist must list each item-level gap exactly once across the whole project, so I add `threads.project_derived(project, graph=..., threads=...)` to threads.py that reuses the SAME per-subject row builder as `_derived` (refactored into `_rows_for_subject`, behavior-preserving) over all local_items, plus the new verdict + fork rows read from threads_projection. The CLI renders; it computes no fold/coverage/check.

6. Derived row order (OWQ #2 below): coverage < verdict < blocked < check < citation < fork (the §5 table's order), then by ref. Project-wide derived is one flat sorted list (OWQ #3: per-kind vs per-item grouping for thread-less project rows — recommend flat sorted by kind-then-ref, matching the projection's existing derived sort posture).

7. Concluding verdict with open tasks at its tip (binding rule 5): in the authored block, the thread's `Verdict: accepted (...)` line prints together with (directly above) that tip's open tasks, reusing cmd_thread's verdict line + "concluding, N open task(s) at this tip". A verdict never prints alone in the worklist.

8. --as-of: relative spans ONLY under it (same as thread). No --as-of -> absolute declaring date, no relative span, byte-identical across wall clocks. --json + --as-of refused (exit 2), like thread.

9. --json (OWQ none): prints {"threads": <threads_projection list>, "derived": <project-wide derived rows>} with cmd_index's json.dump posture (indent=2, ensure_ascii=False, default=str). Load-write notices + diagnostics go to stderr (like cmd_index; H7b review found cmd_thread still does this to stdout — cmd_work does it right). Valid JSON on stdout even on a first run that mints keys.

10. Exit codes: read/list command. 0 on success (a non-empty worklist does NOT change the exit code — it is not a gate; H8 is the gate; recorded here per TASK recommendation, docs say nothing to the contrary). 1 when files failed to load (cmd_ls/cmd_thread posture: report on stderr, answer intact). No exit-2 naming path (work takes no ref); only a bad --as-of or --json+--as-of combination exits 2.

cli.py: only the shared-rendering refactor (extract _task_row_line, _verdict_lines, _derived_detail from cmd_thread so cmd_work reuses the exact same strings instead of copying) + new cmd_work + its subparser. cmd_thread's output must stay byte-identical (test_thread_cli.py pins exact strings).
threads.py: add project_derived() + _rows_for_subject() (behavior-preserving extraction of _derived's loop body) + verdict/fork rows; threads_projection's own output is unchanged.
Nothing else in H7b (chains.py, tests/test_thread_cli.py) is modified.
