- **Prefix renames no longer rewrite bare references, and no longer touch the id ledger** (docs/design/keys.md §4). `refdes revise`/`standard upgrade` now run the same key maintenance every writable command performs (mint keys, expand `links:`/`checks: against:` to `DISPLAY@key` composites, freeze `follows:`) inside the rename's own transaction, and refuse with file:line if a structured reference to an affected id is still bare afterwards -- rewriting bare text is what surrogate keys made unnecessary. A `--dry-run` simulates the whole run -- key pipeline, rename, and post-rename display-half refresh -- on a throwaway copy of the tree, and its changed-file list and per-line report match what the real run writes, file for file. `.refdes/ids.yaml` is left alone: burned/allocated history is a fact about the past, not current vocabulary. Baseline and seal records keep their stamp-time record keys across a rename (only the hash moves). `former-ids propose` on a baseline that carries surrogate keys now returns exact key-proven matches ("exact match (surrogate key)") instead of similarity scores; similarity scoring remains for legacy keyless baselines.
