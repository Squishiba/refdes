- `checks: [{value, against}]` is now rename-safe: `against:` expands to a `DISPLAY-ID@key` composite the same way a structured link target does, with the same stale-label refresh, crossed-reference warning, and malformed/unknown-key diagnostics. `refdes keys adopt` expands existing `against:` references too, reported on their own line.
- A `checks:` inherited from a file's `defaults:` block is expanded and refreshed the same way: its single shared spelling in the defaults block becomes `DISPLAY-ID@key` once, every inheriting item resolves through it, and renaming the checked-against item refreshes that one spelling while leaving every inheriting item's content hash alone. `--no-write` still leaves it bare, an item that declares `checks:` itself keeps its own span, and `refdes revise` prefix renames no longer refuse over a defaults-inherited reference.
- Content hashing moves to `hash_format: 3`: a `checks:` entry's `against:` is reduced to the target's resolved key for hashing, so renaming a checked-against item no longer churns the checking item's hash. Existing `hash_format: 1`/`2` baselines and seals migrate to 3 automatically wherever the recorded hash still matches the item's current content under the old definition; anything else is left untouched and reported as uncomparable rather than guessed at.
