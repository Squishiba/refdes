- Docs: `getting-started.md` showed `items/` in the tree `refdes init` produces. `init` writes only `refdes-project.yaml` and `.vscode/settings.json`; the folder is yours to create.
- Docs: the `refdes id` sample output in `getting-started.md` and `ids.md` was off. `REQ-PWR-002` is allocated at `power.yaml:13`, not `:12` (allocating the first item inserts both `id:` and `key:`, shifting the second down), and the line carries one space after the closing parenthesis, not two.
- Docs: `getting-started.md` said a `bound` "was called `constraint` up to `hardware@2`". The rename happened *at* `hardware@2` — `constraint` is the `hardware@1` name.
- Docs: `authoring.md` listed the display-title precedence as `title` → `text` → `body` → `summary` → `name` → `id`. The engine tries `title`, `text`, `summary` and `name` first and only then falls back to `body`, so a log entry with both a `summary` and a body is titled by its `summary`, not its body.
- Docs: the list-file example in `authoring.md` set `status: accepted` on a `requirement`, whose status choices are `draft`/`active`/`retired` — the example failed the build. It now uses `active`.
- Docs: the reserved-keys table in `authoring.md` omitted `workspace`, `key` and `former_ids`, all of which the parser reserves. Its closing note about the starter `log` type keeping a hand-typed `board` field was removed: no bundled standard version has ever declared one.
- Docs: `authoring.md` counted the standard's types as "the other five"; `hardware@3` ships seven, including `group`. `concepts.md`'s opening list of item types likewise omitted `group`.
- Docs: eleven examples across `ids.md` and `checks.md` used `text:`, the `hardware@2` field name. At `hardware@3` that is a build error (`'requirement.text' is now 'requirement.body'`) and the item does not load. All are now `body:`.
- Docs: a bound example in `checks.md` said "`%` is not a unit" and wrote `<= 0.01` by hand. `%` is understood: `<= 1 %` parses and reads as `0.01`.
- Docs: two links in `coverage.md` pointed at `links.md#blocked-by-and-the-cascade-report`; GitHub keeps the underscore in that heading's slug, so the anchor is `links.md#blocked_by-and-the-cascade-report`. Both resolve now.
