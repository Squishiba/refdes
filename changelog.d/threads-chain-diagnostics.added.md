- `follows:` chains are now walked, not just resolved: an entry's current tip, the thread's current value of a field (`chains.resolve_current`), fork and cycle diagnostics (docs/design/threads.md §3, §6, Phase 2b). An entry with two or more entries following it gets an `info` naming both — an unmerged fork reads as unsettled, never as settled, until an entry declaring `follows:` on both tips closes it. A `follows:` cycle is a build error naming the whole cycle once, the same shape `blocked_by` cycles already take. `follows:` still isn't part of the bundled standard, so a project sees any of this only if its own schema declares a link literally named `follows:`.
