- Theming step 2b: three built-in themes besides `default` — `high-contrast`, `paper`, `slate` — each passing WCAG AA contrast in both palettes, and a generated gallery page (`docs/themes.md`, `python docs-site/gen_themes.py`) showing every theme's effective token table.
- `site: tokens:` can now target one palette: nest overrides under `light:` and `dark:` headings. A bare `--token` pair keeps its meaning and applies to both palettes.
- The verdict colours `--good`, `--bad`, `--warn` and `--claim` can be overridden. Every semantic pair in the effective palettes is contrast-checked at load — 4.5:1 against `--bg`/`--panel`, plus a hue-separation rule keeping `--bad` distinguishable from `--good` — and a failing pair is a warning naming the pair and the measured ratio, never a blocked build. Values the checker cannot parse as hex are skipped.
- A light-mode token override no longer bleeds into dark mode: when the two palettes disagree, the generated `theme.css` re-asserts the effective dark palette inside the `prefers-color-scheme: dark` block, and emits `[data-theme="light"]` / `[data-theme="dark"]` blocks so a host page can pin a mode.
