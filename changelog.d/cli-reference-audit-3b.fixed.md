- CLI reference: `refdes former-ids propose` only ever documented the `confidence 94%` candidate line, which is the legacy keyless-baseline path. Against a baseline stamped today the pairing comes from surrogate-key identity and the line instead ends in `exact match (surrogate key)` — the form a current user normally sees, since keys are minted automatically. Both forms are now shown.
- CLI reference: `refdes former-ids propose` exits 1 before proposing anything when no baseline has been stamped yet or when `--baseline NAME` names nothing. Both messages are now documented, as is the fact that a `--confirm` naming a non-candidate still prints the candidate list first.
- CLI reference: `refdes history` subcommands were missing from the global `--no-write` table's list of commands that refuse to run, even though the `history` section states it and `refdes --help` lists them.
- CLI reference: `refdes history capture` on an unknown item and `refdes history redact` on a target that is neither an item nor a 64-hex digest both refuse with exit 2; `history redact` on a target that resolves but has nothing captured exits 0 with `no history objects or events matched ...; nothing was redacted` and does not print the Git warning. All three are now documented.
- CLI reference: `refdes history migrate-seals` documents only the `differs` outcome of `--capture-current`, and not the `unresolved` one, the `already migrated` line a repeat run prints, or the `no legacy seal files found; nothing to migrate` a project with no seals yet gets (exit 0).
- CLI reference: the `refdes stub-tests` sample output listed its ids unsorted and mixed another board's id into a single board's file. Ids are sorted within each file, and each file only ever holds stubs from its own (workspace, board) scope.
