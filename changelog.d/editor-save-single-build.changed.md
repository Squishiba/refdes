- Editor saves do one full project build instead of two. The before-edit snapshot was loaded with `loader.load_readonly` (parse + build), but nothing read its build output unless the delta diagnostic gate had an error to compare — so the build is now deferred to the gate and skipped entirely on a save whose candidate is clean. A save on a synthetic 1600-item project drops from ~530 ms to ~390 ms (~27%); a save the gate blocks costs what it cost before, and refuses with the same diagnostics. The overlay build that validates a candidate edit before any byte is written, the content-revision conflict check, the sealed and imported refusals, and the accept's two-file transaction are unchanged, and an accept still takes its eager build. A project that loads but will not build — a half-written `.refdes/citations.yaml`, say — is still refused as the project rather than as the edit, and the save that fixes it can now land.
