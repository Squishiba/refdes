- CLI reference: `refdes revise` cannot perform a **type** or **required-field** rename on a hand-rolled schema, in either order. The old text said to "pair the rename with your own edit to `refdes-schema.yaml` (in whichever order makes both sides agree once both are done)", but `revise` validates the project both before and after the rewrite, and neither state is valid on its own: data-renamed-only gives `unknown type 'spec2'. Did you mean 'spec'?`, schema-renamed-only gives `unknown type 'spec'. Did you mean 'spec2'?`. `revise` refuses on a project that already has build errors and refuses one the rewrite would break, so both orders are refused and both leave the project untouched. The section now says a type or required-field rename is a hand edit to both files made together, and names the renames `revise` *can* do alone there (prefix, id, and optional-field). The code path that moves schema and data together in one operation (`revise.apply(..., mutate_config=...)`) is reachable only from `refdes standard upgrade`, not from the CLI.
- CLI reference: `refdes calc-rewrite` does **not** rewrite a line whose old annotation carried a tolerance, contrary to the documented `P : W ± 10% = V * I` → `P = V * I ± 10% | W` example. That is the right transformation and the build error quotes it verbatim, but the command refuses the file: `a rewritten calc changes meaning: … P: was '' in unit 'W ± 10%', now evaluates to '14.4 W' in unit 'W'`. Known source inconsistency, reproduced in three projects; documented as "apply that one line by hand, then re-run" rather than presented as a workflow.
- CLI reference: the global `--no-write` table listed only `id`, `revise` and `stub-tests` as dry-run commands that report and write nothing; `calc-rewrite` behaves the same way and was missing.
- CLI reference: the "Files the tool writes" table omitted `.refdes/keys-adopted.yaml`, which the `refdes keys adopt` section tells you to commit, and listed only `refdes revise` and `refdes standard upgrade` as commands that rewrite a baseline — `refdes calc-rewrite` carries content and calc hashes forward across baselines too.
