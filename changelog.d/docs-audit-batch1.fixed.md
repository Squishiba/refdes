- Docs: `markdown.md`'s closing example named "a requirement's `text`", the `hardware@2` field name. At `hardware@3` the field is `body`.
- Docs: the local-path citation example in `markdown.md` was a `bound`, and `hardware@3` declares `citations` on `decision` and `component` only, so it built with `unknown field 'citations' on bound`. It is now a `component`.
- Docs: `math.md`'s display-units table listed results that do not follow from its expressions (`volt * ampere` evaluates to `1 W`, not `3.96 W`; `millivolt / ampere` to `1 mΩ`, not `41.67 mΩ`; `1 / microsecond` to `1 MHz`, not `454.5 kHz`). Corrected to the values that actually render.
- Docs: `math.md` said `min` and `max` "take two or more". Both are fully variadic — `min(1)` evaluates — so the sentence now says any number of arguments.
- Docs: `math.md` told a reader with a torque value to "pin it with `tq = ... | N*m`". A unit assertion pins a scale (`0.2366 W/in^2 | mW/in^2` renders `236.6 mW/in²`) but does not stop the compound-to-named collapse: `2 N·m | N·m` and `2 N·m | N*m` both still render `2 J`. The sentence promising a pin was removed.
- Docs: `math.md`'s "Errors you will see" block said "cannot divide by a value whose tolerance range includes zero". The real message is `division by a value whose tolerance range includes zero`; the stray word is gone.
- Docs: two `[below](#…)` pointers in `links.md` were dead — GitHub keeps the underscore in a heading's slug, so the anchors are `#governed_by-vs-refines-vs-constrained_by` and `#blocked_by-and-the-cascade-report` (the second is the anchor the previous audit corrected `coverage.md` to use).
- Docs: `links.md` said the standard library declares the vocabulary "for the six standard types". `hardware@3` ships seven, `group` included.
- Docs: `links.md` said writing `follows:` today "is an unknown-link error". No bundled standard declares the verb, so the loader reports `unknown field 'follows' on <type>` as a *warning* and the build still exits 0. The paragraph now says so, and names what a reader would actually see.
- Docs: `blocks.md` called the `blocked_by:` cascade report "a separate, not-yet-implemented feature" on the same page that later describes its three surfaces as existing. It ships: `refdes audit` prints a "Blocked chains:" section, the blocked item's page carries a chain panel, and the stale-blocker check is an `info`.
- Docs: `pages.md` and `output.md` said a narrative page's on-page contents list "highlights the section currently in view as you scroll". The scroll-spy (`app.js`, `IntersectionObserver`) is wired to `document.html`'s own `.toc`/`.doc-item`, never to a page's `.page-toc`; the page list is sticky and always a plain list of working anchors.
- Docs: `pages.md` closed its pages-only example with "A schema block is still required by the config format, even when nothing uses it." `refdes-schema.yaml` is optional — a pages-only project with no schema file at all builds clean. The sentence was removed.
- Docs: the `site.tokens:` example in `output.md` and in `themes.md` mixed a bare `--token: value` pair with `light:`/`dark:` headings. That combination is refused at load: "A tokens: block that uses the light and dark headings may contain only them." Both examples were split, and the rule is now stated.
