- CLI reference: `refdes audit` prints an `Older baseline keys no current item declares:` section on every run, including `(none)` on a project with no baselines at all; the sample output and the opening summary list omitted it entirely. The `Baselines:` section's `most recent release: (none stamped yet)` line (revision stamped, no release) and the `unpinned` form of an `Imported projects (read-only):` line are now documented too.
- CLI reference: `refdes new` has an undocumented `--list` flag that prints a list-file skeleton (`defaults:` plus an `items:` list with one empty entry) instead of a single item, e.g. `refdes new component --list > items/power/candidates.yaml`. Its output is also front matter *plus* a body stub, not front matter alone.
- CLI reference: `refdes schema --graph` without a `TYPE` prints one SVG document per type plus the coverage spine, all concatenated — eight documents for a `hardware@3` project — so the documented `refdes schema --graph > graph.svg` does not produce a valid SVG file. The `TYPE` positional, which draws a single type's diagram, was undocumented; so was the unknown-type exit-1 error. The per-drawing byte-for-byte claim against the built vocabulary page was verified and kept, narrowed to the matching page.
- CLI reference: `refdes schema` does not write `.refdes/schema.json`, contrary to "and this command itself" in the list of commands that refresh it. That list was also incomplete: `ls`, `revision`, `release`, `stub-tests`, and `former-ids` refresh it too, while `new` and `schema` do not. `--json` is the default, so a bare `refdes schema` prints the same document.
- CLI reference: `refdes standard add-preset`/`remove-preset` exit 2 without writing when asked to add a preset that is already selected or remove one that isn't; the exit-1 removal path's `N error(s) above -- fix these, or add the preset back` guidance is now documented.
- CLI reference: `refdes standard upgrade --to N` is forward-only and refuses up front (exit 2, nothing written) when the project is already at or past `N` or `--to` is not an integer; a `--to` past the newest bundled version is instead caught by post-rewrite validation (exit 1, config unchanged). Both behaviours are now stated.
- CLI reference: `refdes init`'s name checks — an unknown `--standard`, an unknown `--preset`, a preset combined with `--standard none`, an existing `refdes-project.yaml` — are all exit-2 configuration errors that write nothing, and `init` writes to the current directory regardless of the global `-c`.
