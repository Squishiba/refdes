- `--no-write` now suppresses every write the tool performs while loading, checking, or building a project — `.refdes/schema.json` regeneration (the staleness warning still fires, reporting it was not refreshed), the seal files and the membership manifest written by `build`, the baseline hash-format migration reached from `former-ids propose`, and the baseline stamp itself (`revision`/`release` report what they would stamp and write nothing). Explicit write commands either honor the flag by running their existing dry-run (`id`, `revise`, `keys adopt`, `stub-tests`) or refuse with a clear message and exit 2 (`fetch`, `init`, `standard upgrade`, `standard add-preset`/`remove-preset`, `former-ids propose --confirm`). `refdes build --no-write` still writes the site output directory — that is the command's own product, not a side effect (docs/design/keys.md §2).
